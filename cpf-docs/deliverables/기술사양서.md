## 3. Package Boundary

```text
com.cpf.<owner>.api       공개 호출 계약
com.cpf.<owner>.spi       Provider/Extension 계약
com.cpf.<owner>.internal  Owner 내부 구현
```

Public API는 Semantic Version과 Compatibility 대상이다. SPI는 Lifecycle·Failure·Thread-safety·Capability·Version을 JavaDoc에 기록한다. Internal은 다른 Module에서 Compile되지 않아야 한다.

## 4. 공통 요청 문맥

| 논리 필드 | 형식·규칙 | 생성·전파 | 용도 |
|---|---|---|---|
| transactionId | 제품 표준 길이·문자 규칙 | 진입점 생성, 전 구간 전파 | 온라인/배치/메시지 상관 |
| traceId/span | W3C Trace Context | 진입 또는 상위 호출 | 분산 추적 |
| operationId | 불변 UUID/제품 ID | Command 수락 시 생성 | 비동기 상태·대사 |
| businessKey | 업무 고유키 | 업무 요청자 | 원장 조회 |
| idempotencyKey | 업무 범위 내 유일 | 호출자 생성·Replay 유지 | 중복 효과 방지 |
| requestHash | 정규화 Payload Hash | 수신측 계산 | 같은 Key 다른 요청 거부 |
| expectedVersion | 정수/ETag 의미 | 조회 Version 전달 | 낙관적 동시성 |
| deadline | 절대시각 또는 남은 예산 | 진입점 설정·하위 배분 | Timeout Budget |
| actor/roles/dataScope | 인증 문맥 | Security Adapter | 권한·Masking |
| reason/approval | 사유·정책 Version·승인 ID | 위험 Command | 감사·통제 |
| attempt | 1부터 증가 | 외부/Broker 호출 | 시도 이력·Retry |

실제 Wire Header 이름은 `cpf-core` 공개 Header 계약과 OpenAPI를 단일 정본으로 한다. 문서·Client·Gateway가 별도 Alias를 만들지 않는다.

## 11. TCP·ISO8583 사양

- Mode: CLIENT/SERVER
- Frame: FIXED/LENGTH_HEADER/STX_ETX/CRLF
- Encoding: UTF-8 또는 승인 Charset
- 최대 Frame: 기본 1 MiB
- Correlation: 요청/응답 Key와 Pending/Orphan 상한
- TLS/mTLS: KeyStore·TrustStore·Secret Reference
- Reconnect: Initial 200ms, Max 30s, Jitter 0.2 기본
- ISO8583: Primary/Secondary Bitmap, Field Spec, Binary/BCD/Hex, MAC Provider, Sensitive Field Masking
- Timeout 뒤 Unknown Result Store와 기관 조회로 확정

## 18. Query 계약 상세

- 검색 Field는 이름·Type·Default·허용 연산·최대 기간을 명시한다.
- Sort Field Allowlist와 안정적 Tie-breaker(PK)를 사용한다.
- Cursor는 Filter/Sort/Version과 서명 또는 위변조 방어를 포함한다.
- Data Scope와 Masking을 Query Plan과 결과 Mapping에 적용한다.
- Count는 비용이 큰 경우 Exact/Approx/Unknown을 구분한다.
- Read Model은 기준 시각·지연·정본 Owner를 반환한다.
- Timeout은 같은 조건·기준 시각·Cursor로 재조회할 수 있게 한다.

## 23. Provider Binding Specification

- Binding Name은 Runtime 내 유일하다.
- Default Binding은 Capability별 하나다.
- 후보 Map 검증 후 원자적으로 Registry를 갱신한다.
- Provider가 0개 또는 Default가 둘 이상이면 기동을 거부한다.
- Profile 허용 목록 밖 Provider를 Generator와 Runtime이 모두 거부한다.
- Provider 교체는 In-flight·Offset/Queue·Ledger·Secret·Schema·LKG를 포함한다.
