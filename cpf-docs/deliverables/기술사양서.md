## 1. 공통 계약

### 식별자

| 필드 | 용도 | 규칙 |
|---|---|---|
| `transactionId` | 요청·DB·로그·감사 연결 | 생성 후 호출 체인에서 유지 |
| `traceId` | 분산 추적 | Trace Backend와 구조화 로그에서 일치 |
| `operationId` | 장기 실행·운영 Command 식별 | 재시도 시 유지 |
| `businessKey` | 업무 원장과 대사 | 업무 시스템이 정의 |
| `idempotencyKey` | 중복 실행 방지 | 같은 업무 효과에는 같은 키 사용 |
| `attemptId` | Provider 시도 구분 | 재시도마다 새 값, 원 요청과 연결 |
| `fencingToken` | 임대 소유권 검증 | 증가 방향이며 쓰기 직전 검증 |

### 결과 분류

```text
SUCCESS
REJECTED
FAILED_RETRYABLE
FAILED_FINAL
PARTIAL_SUCCESS
UNKNOWN_RESULT
```

`UNKNOWN_RESULT` 반환 시 반드시 상태 조회 또는 대사 Command를 제공한다.

## 2. Public API·SPI·Internal

| 분류 | 사용 대상 | 호환성 |
|---|---|---|
| Public API | 업무 Domain·제품 Consumer | Version 정책, JavaDoc, Example, Contract Test 필요 |
| SPI | 조직별 Provider Plugin·선택 Adapter | Backoff·Fail-closed·Provider Capability 선언 필요 |
| Internal | 동일 Artifact 내부 | 외부 Consumer 직접 참조 금지 |

Package 이름이나 Interface 존재만으로 공개 계약이 되지 않는다. 게시 POM, JavaDoc, 소비 예제와 Compatibility Test가 함께 있어야 한다.

## 6. Capability Profile

Profile 입력 예:

```yaml
profile: DOMAIN_EVENT_RABBITMQ
profileVersion: 1
bindings:
  default:
    provider: rabbitmq
```

필수 생성 결과:

```json
{
  "profile": "DOMAIN_EVENT_RABBITMQ",
  "profileVersion": 1,
  "resolvedStarters": [
    "cpf-starter-base",
    "cpf-starter-messaging-reliability-jdbc",
    "cpf-starter-messaging-rabbitmq",
    "cpf-starter-observability"
  ],
  "starterVersionLock": "<hash>"
}
```

현재 `create-domain.ps1`는 `Capabilities`, `Messaging`, `External`, `File`, `SecurityAudit` 등 입력을 받지만 위 Profile·resolved lock을 제공하는 상태는 확인되지 않았다.

## 7. Messaging 사양

### 공통 Envelope

```json
{
  "messageId": "...",
  "correlationId": "...",
  "causationId": "...",
  "transactionId": "...",
  "idempotencyKey": "...",
  "schema": "...",
  "schemaVersion": 1,
  "occurredAt": "...",
  "producer": "...",
  "payload": {}
}
```

### 공통 Reliability

- Outbox는 업무 Commit과 같은 Local Transaction에서 기록한다.
- Inbox/Dedup은 Consumer 효과와 같은 Local Transaction에서 기록한다.
- Claim은 Lease와 Fencing Token을 사용한다.
- Retry가 끝나면 DLQ/DLT로 이동하고 Reason·Attempt·Payload Hash를 기록한다.
- Replay는 승인·Reason·대상 범위·Dry Run·감사를 요구한다.
- Publish ACK 유실은 재발행 전에 Provider Receipt와 Outbox를 대사한다.

### Provider별 필수 항목

| Provider | 필수 계약 |
|---|---|
| Kafka | ACK, Offset Commit, Rebalance, Ordering, Retry/DLT, Lag, Replay |
| RabbitMQ | Exchange/Queue/Binding, Confirm, Return, Manual ACK/NACK, DLX/DLQ, Prefetch, Cancellation |
| JMS | Queue/Topic, Durable Subscription, Selector, Ack Mode, Session Transaction, Redelivery |
| IBM MQ | Queue Manager, Channel, TLS, Credential Rotation, CCDT/Endpoint, Reason Code, In-doubt |

다중 Provider는 Named Binding을 사용하고 Default Binding은 최대 하나다. 이름 없는 Client가 둘 이상이면 Startup을 실패시킨다.

## 8. TCP·전문·ISO8583

### Frame Mode

```text
FIXED_LENGTH
LENGTH_HEADER
STX_ETX
CRLF
CUSTOM_CODEC
```

필수 설정:

| 설정 | 의미 | 검증 |
|---|---|---|
| connect/read/write timeout | 연결·응답 시간 예산 | 0 또는 음수 거부 |
| maxFrameBytes | 과대 Frame 차단 | 초과 시 연결·메시지 정책 명시 |
| charset | UTF-8·EUC-KR·EBCDIC 등 | Encode/Decode Round Trip |
| poolSize | 연결 수 | Queue·Backpressure와 함께 검증 |
| heartbeat | Half-open 감지 | 누락·지연 Fault Test |
| tls/mTLS | 인증·암호화 | 인증서 만료·교체 시험 |

Write 완료 후 Response가 유실되면 재송신 전에 Correlation·업무 원장·상대 Receipt를 조회하고 `UNKNOWN_RESULT`를 대사한다.

## 9. SFTP 사양

Operation:

```text
UPLOAD
DOWNLOAD
LIST
MOVE
DELETE
RECONCILE
```

필수 결과에는 Remote Path, Size, Checksum, Attempt, Temporary Path, Final Rename, Transfer Ledger ID가 포함된다. 업로드는 임시 이름으로 전송한 뒤 Checksum 확인 후 Atomic Rename을 사용한다. 재개는 Remote Size와 Chunk Checksum이 일치할 때만 허용한다.

## 10. Notification 사양

- Notification Core는 Outbox·Worker·Retry·DLQ·Preference·Quiet Hours·Audit를 소유한다.
- Email Starter는 SMTP/Provider, Template, Attachment, Bounce를 소유한다.
- SMS SPI는 Provider Plugin, Rate Limit, Receipt, Callback을 정의한다.
- Provider가 요청을 수락한 뒤 응답이 유실되면 새 메시지를 만들지 않고 Provider Receipt를 대사한다.

업무 식별자·계좌·Token·Password를 Metric Label에 사용하지 않는다.

## 14. Artifact·Supply Chain

- Leaf Starter는 독립 JAR·POM·Sources·JavaDoc를 게시한다.
- BOM은 모든 승인 Artifact의 Version Constraint를 제공한다.
- SBOM에는 실제 Runtime Classpath와 Provider SDK가 드러난다.
- Provenance는 Source SHA·Build Command Hash·Artifact Hash를 포함한다.
- Aggregate Starter는 고유 Source와 AutoConfiguration이 없어야 한다.

## 15. 오류와 복구

| Failure Class | 기본 행동 |
|---|---|
| Validation | 재시도하지 않고 입력 수정 |
| Authorization | 권한·Data Scope·Approval 확인 |
| Conflict | Expected Version과 현 상태 조회 후 재결정 |
| Retryable Infrastructure | 같은 Idempotency Key와 Budget 안에서 재시도 |
| Unknown Result | Provider/업무 원장 대사 전 재실행 금지 |
| Partial Success | 성공 대상을 유지하고 실패 대상만 재처리 |
| Final Failure | 보상·수동 조치·감사 기록 |
