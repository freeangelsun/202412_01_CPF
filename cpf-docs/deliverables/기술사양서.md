## 2. Public API/SPI/Internal

- Public API: `com.cpf.<owner>.api`
- Extension SPI: `com.cpf.<owner>.spi`
- Internal: `com.cpf.<owner>.internal`과 내부 Starter Package
- Public DTO에 Spring·Kafka·JMS·JDBC Driver·Resilience4j Type을 노출하지 않는다.
- Public API/SPI는 Version·Compatibility·Failure·Thread-safety 계약을 문서화한다.
- Internal은 외부 Module Compile과 Publication Surface에서 차단한다.

## 4. 결과와 오류

| 결과 | 의미 | 재실행 |
|---|---|---|
| SUCCESS | 부작용과 결과가 확정 | 불필요 |
| FAILED | 명시 실패가 확정 | 분류 정책에 따름 |
| UNKNOWN | 부작용 결과가 미확정 | Reconcile 전 금지 |
| PARTIAL | Target 일부만 반영 | 실패 Target만 |

오류 분류는 Validation, Unauthorized, Forbidden, Not Found, Conflict, Timeout, Dependency Failed, Unknown Result, Partial Apply다.

## 6. Data 계약

대표 API는 `CpfDataOperations`, `CpfJdbcOperations`, Vendor SQL Catalog다.

- DataSource·Vendor·Read/Write Routing·Query ID를 명시한다.
- Parameter는 Bind Variable을 사용한다.
- Update/Delete 영향 건수를 검증한다.
- Pagination은 안정적인 정렬과 Cursor를 사용한다.
- Cache는 Source of Truth와 Evict/Reconcile 계약을 가진다.
- Distributed Lock을 Local Cache와 같은 의미로 사용하지 않는다.

## 7. Messaging 계약

대표 계약: Broker Client, Publish Request/Result, Provider SPI, Result Probe, Unknown Result Port와 Reconciler.

Publish Request에는 Binding Name, Key, Payload Type/Version, Headers, Idempotency Key, Deadline을 포함한다. Result에는 Provider Message ID, Tracking ID, Attempt, 상태와 Error를 포함한다.

Default Binding이 없거나 둘 이상이면 명시 Binding 없이 발행하지 않는다.

## 8. Notification 계약

Notification Request에는 Template, Channel, Recipient, Variables, Idempotency Key와 Deadline을 포함한다. Result/Receipt는 Provider Tracking, Delivery 상태, Attempt와 Error를 제공한다.

수신자와 본문은 Log/Audit에서 Masking한다.

## 9. Integration 계약

| 기능 | 계약 |
|---|---|
| HTTP | Target ID·Method·Path·Header·Timeout·UNKNOWN |
| Resilience | Operation 정책·Retry Class·Circuit·Bulkhead |
| TCP | Framing·TLS·Correlation·Read/Write Timeout |
| Fixed-length | Layout Version·Length·Padding·Charset |
| ISO8583 | MTI·Bitmap·Field Spec·MAC·Reversal |
| SFTP | Host Key·Path Policy·Checksum·Resume·Ledger |

## 10. File 계약

Attachment는 Size·Count·MIME·Extension·Checksum·Security Scan을 검증한다. Archive는 Zip Slip, Entry·Expanded Size·Depth를 제한한다. Tabular는 Sheet·Row·Column·Cell 한도를 둔다.

## 11. Feature Flag

Flag Key, Type, Default, Context, Provider, Evaluation Reason과 Audit를 반환한다. Override는 Target, 조건, 시작/종료, Reason, Approval과 Expected Version을 가진다. Kill Switch는 CRITICAL 조치다.

## 12. Resilience

Policy는 Timeout, Retry Count/Backoff, Circuit Threshold, Bulkhead, Failure Classifier를 포함한다. 비멱등 Operation은 Retry 대상이 아니다. 정책 적용 결과와 Audit를 제공한다.

## 13. Runtime Control

Request에는 Preview Hash, Target Set, Desired Version, Expected Current Version, Reason, Approval과 Expiry를 포함한다. Target은 ACK/NACK, Applied Version, Observed Hash와 Error를 보고한다.

## 14. ADM Route 계약

Route 정본은 `cpf-admin/frontend/src/app/routes.ts`, API 정본은 `cpf-admin/frontend/openapi/cpf-openapi.json`이다.

Route는 Route ID, Path, Menu ID, Label, Group, Owner, Risk, Feature Flag, Expected Operation IDs와 Component를 가진다. Operation ID 불일치는 Frontend Gate에서 차단한다.

## 15. BZA Route 계약

BZA Route는 조직·직원·발령·사용자·Role·Permission·결재·위임·Session·Audit·Attachment·Download를 제공한다. 각 Route는 Menu Code와 Expected Operation IDs를 가진다.

## 16. Gateway 계약

Route, Predicate, Filter, Rewrite, Target Group, Authentication, Timeout, Retry, Idempotency, Attempt Ledger, Version, Checksum과 Publish 상태를 제공한다.

## 17. DB 사양

공식 Vendor는 Oracle, PostgreSQL, MariaDB다. 모든 객체는 Install·Migration·Rollback·Verify·Checksum과 Owner·Consumer를 가진다. 상태·Version·Audit·Idempotency·Lease/Fencing Column은 적용 범위에 포함한다.

## 18. Artifact 사양

정본은 `cpf-tools/release/cpf-final-artifact-catalog.json`이다. Artifact는 ID, Owner Path, Kind, Producer, Output Pattern, Consumer와 Required Attestation을 가진다.

## 19. Health·Metric·Trace

Health는 Liveness, Readiness, Dependency, Degraded, Unknown을 구분한다. Metric은 Result·Latency·Retry·Circuit·Queue·Lease·UNKNOWN을 구분한다. Trace에 Payload·Secret·개인정보 원문을 넣지 않는다.
