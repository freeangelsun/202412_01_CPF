## 2. 표준 식별자

| 식별자 | 목적 |
|---|---|
| Transaction ID | 한 업무 요청의 전체 흐름 |
| Trace ID | 분산 Trace |
| Operation ID | 상태 변경·운영 조치 |

| Target ID | 외부기관·Instance·배포 대상 |

| Approval ID | 위험 조치 Snapshot |
| Audit ID | 변경 Evidence |

## 3. 상태 계약

`REQUESTED`, `RUNNING`, `SUCCEEDED`, `FAILED`, `UNKNOWN_RESULT`, `PARTIAL`, `ROLLED_BACK`, `PARTIALLY_ROLLED_BACK`를 공통 운영 언어로 사용한다. 제품별 상세 상태는 이 의미를 축소하지 않는다.

## 4. HTTP 계약

- Query: GET, 부작용 없음, 기준시각·Owner·Version 포함.
- Command: POST/PUT/PATCH, Reason·Version·Idempotency·Operation 반환.
- Error: Code·Message·Transaction·Operation·Retry 의미.
- Export: 별도 Job·Permission·Reason·만료·Download Audit.

## 5. OpenAPI WebMVC

Prefix `cpf.openapi.webmvc`의 Enabled·API Docs·Management·Path·Title·Version·Instance·Refresh Interval을 제공한다. Operation ID는 Generated Client·ADM Route·Permission과 일치해야 한다.

## 부록 A. 기능 계약 사양

| 계약 | 필수 입력 | 상태·결과 | 오류·복구 |
|---|---|---|---|
| Versioned Command | businessId, expectedVersion, reason, idempotencyKey | COMPLETED/CONFLICT/UNKNOWN | 409 재판단, Operation 대사 |
| Query | filter, page, size, sort, actor scope | Page + 기준시각 | 400 Field Error, 403 Scope |
| Event | eventId, aggregateId, schemaVersion, payloadHash | Outbox→Published→Inbox | Retry/DLQ/Replay |
| External Attempt | operationId, target, requestHash, deadline | STARTED/SUCCEEDED/FAILED/UNKNOWN | Status Query/Reconcile/Compensate |
| Batch Execution | job, version, identifying parameters, selectionHash | STARTING~COMPLETED/UNKNOWN | Stop/Restart/Reprocess/Reconcile |
| Approval | policyVersion, immutable snapshot, requester, expiry | REQUESTED/APPROVED/REJECTED/EXPIRED/EXECUTED | 새 요청·실행 차단 |
| Runtime Apply | desiredVersion, checksum, targets | ACK/NACK/PARTIAL/DRIFT | Reapply/LKG Rollback |
| Download | query snapshot, reason, masking policy, expiry | CREATED/READY/EXPIRED/FAILED | 재생성·Audit 보존 |

## 부록 B. 비기능 사양 판정 항목

- 모든 Timeout은 상위 Deadline보다 짧고 Retry Backoff를 포함한다.
- 모든 Queue·Batch·Download·Archive는 Size/Count/Time 상한을 가진다.
- 다중 Instance Writer는 Lease와 Fencing으로 stale write를 차단한다.
- 민감정보는 Log·Metric Tag·Trace Attribute·Error·Evidence에 원문으로 남지 않는다.
- Runtime 상태는 Durable 원장과 연결되고 화면 Snapshot만 정본으로 사용하지 않는다.
- Local/Remote·DB Vendor·Mixed Version 차이는 Contract Test로 검증한다.
