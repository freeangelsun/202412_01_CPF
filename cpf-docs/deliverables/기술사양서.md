## 2. Public Contract 규칙

- Public API: `com.cpf.<owner>.api` 또는 Catalog에 선언된 Public Package
- Customer Extension SPI: `com.cpf.<owner>.spi`
- Internal: `com.cpf.<owner>.internal` 및 Internal Starter 구현 Package
- Public DTO에 Spring, Kafka, RabbitMQ, JMS, IBM MQ, JDBC Driver, Resilience4j 등 Provider 타입을 노출하지 않는다.
- 상태 변경 요청은 `idempotencyKey`, `expectedVersion`, `reason`, `actor` 중 적용 항목을 포함한다.
- 결과는 `SUCCESS`, `FAILED`, `UNKNOWN`을 구분하며 `UNKNOWN`을 성공 집계에 포함하지 않는다.

## 4. Data API

대표 Public API:

- `com.cpf.core.api.database.CpfDataOperations`
- `com.cpf.core.api.database.CpfJdbcOperations`
- `com.cpf.core.api.database.CpfVendorSqlCatalogs`

대표 구현:

- `cpf-starters/data/persistence-jdbc/**`
- `cpf-starters/data/persistence-mybatis/**`
- `cpf-starters/data/cache-caffeine/**`
- `cpf-starters/data/cache-valkey/**`

DataSource 이름, Vendor, Read/Write Routing, Query ID, Parameter, Expected Row Count를 명시한다. Update/Delete 결과가 예상 건수와 다르면 Conflict 또는 Not Found로 분류한다.

Provider:

| RabbitMQ | `cpf-starters/messaging/rabbitmq` | `cpf.messaging.rabbitmq` |

## 11. Runtime Control 계약

변경 요청은 Preview 결과 Hash, Target Set, Desired Version, Expected Current Version, Reason, Approval과 Expiry를 포함한다. Target은 ACK/NACK, Applied Version, Observed Hash를 보고한다. 부분 적용 시 성공 Target을 다시 적용하지 않고 실패 Target만 재시도하거나 전체 Rollback한다.

Owner별 Applier는 각 Capability Starter에 두며 공통 Runtime Control Module에서 Owner 구현 Package를 import하지 않는다.

## 12. ADM API·Route 계약

ADM Frontend Route 정본은 `cpf-admin/frontend/src/app/routes.ts`, API 정본은 `cpf-admin/frontend/openapi/cpf-openapi.json`이다.

신규/현행 Route 예:

| Route | 화면 | Risk | 대표 Operation |
|---|---|---|---|
| `/runtimeControl` | Deployment·Promotion·Rollback | HIGH | Preview/Create/Cancel/Rollback/Verify |
| `/recoveryCenter` | 복구 센터 | MEDIUM | Unknown Resolve, DLQ Replay, Log Recovery |
| `/incidents` | Error·Unknown Result | HIGH | Incident Transition, Signal Ingest |
| `/feature-flags` | Feature Flag | HIGH | Flag 조회·변경·감사 |
| `/resilience-policies` | Resilience Policy | HIGH | 정책 조회·변경·감사 |
| `/batch` | Batch / Center-Cut | MEDIUM | Job/Schedule/Execution/Worker 조회 |

Frontend Generated Client와 Backend OpenAPI Operation ID가 일치하지 않으면 Build Gate를 실패시킨다.

## 13. Artifact·Supply Chain 계약

정본: `cpf-tools/release/cpf-final-artifact-catalog.json`

각 Artifact는 Artifact ID, Owner Path, Producer, Output Pattern, Consumer와 Attestation을 가진다. 공식 DB Vendor는 Oracle, PostgreSQL, MariaDB다. 배포 전 SHA-256, CycloneDX SBOM, License Review, Migration Checksum, Browser Test 중 해당 항목을 확인한다.

## 14. 오류 분류

| 분류 | 의미 | 재시도 | 운영 조치 |
|---|---|---|---|
| Validation | 입력 계약 위반 | 수정 후 | 요청자 수정 |
| Unauthorized/Forbidden | 인증·권한 실패 | 금지 | 권한·Token 확인 |
| Conflict | Expected Version/상태 불일치 | 재조회 후 | 최신 상태로 재판단 |
| Timeout | 시간 예산 초과 | 정책에 따름 | Dependency 상태 확인 |
| Dependency Failed | 외부 시스템 명시 실패 | 제한적 | Retry/DLQ/Incident |
| Unknown Result | 부작용 결과 불명 | 직접 재시도 금지 | Reconcile 후 확정 |
| Partial Apply | 일부 Target만 반영 | 실패 Target만 | LKG/Rollback |
