## 1. 표준 적용 원칙

- MUST 위반은 Build/Release를 차단한다.
- 예외 승인은 ADR·기간·Owner·대체 통제·제거 계획과 승인자를 기록하며 만료 시 표준으로 복귀한다.
- Generated 파일은 원본과 Generator를 수정하고 재생성한다.
- Source·Test·문서·Migration·운영 절차를 같은 변경으로 갱신한다.

## 2. Repository·Git 표준

| 규칙 | 허용 | 금지 |
|---|---|---|
| Branch/Commit | 승인된 작업·의미 있는 Commit | 무단 Force Push/History Rewrite |
| Working Tree | 기존 변경 보호·정확한 Path Stage | 전체 Restore/Clean/Stash |
| 파일 | UTF-8 no BOM·LF·정확한 상대경로 | Root 임시파일·bak/tmp/log |
| Secret | 환경/Secret Provider Reference | Repository 원문 Secret/Key |
| Generated | 원본/Generator/Output 동시 변경 | Output 수동 수정 |
| Evidence | Exact SHA·명령·환경·Exit·Hash | 과거 SHA·미실행 PASS |

## 3. Java·Package·Module 표준

- Java 25 Toolchain을 사용한다.
- `com.cpf.<owner>.api|spi|internal` 경계를 지킨다.
- Public API에 Provider SDK Type을 노출하지 않는다.
- DTO는 Mutable Entity·Persistence Object와 분리한다.
- Nullable·Optional·Collection 의미를 JavaDoc/OpenAPI에 일치시킨다.
- 시간은 `Instant`/`OffsetDateTime`, 기간은 `Duration`을 우선한다.
- 금액은 `BigDecimal`과 Currency/Scale/Rounding을 명시한다.
- Enum은 Unknown/Forward Compatibility를 고려한다.
- Thread·Executor·Queue를 무제한 생성하지 않는다.

## 4. Spring·AutoConfiguration 표준

| 항목 | 필수 | 금지 |
|---|---|---|
| Starter | 단일 Capability·Typed Properties·Validation·Condition | 업무 Bean·Mega Starter |
| AutoConfiguration | 명시 Import·Backoff·Fail-closed | Component Scan으로 숨은 Bean |
| Properties | Prefix·Type·Default·Range·Metadata | Environment 문자열 산발 조회 |
| Bean | 명확한 이름/Qualifier·Default 단일성 | Provider 둘 이상 Primary |

| Async | Bounded Executor·Context 전파 | Common Pool 무제한 사용 |

## 5. API 표준

- Resource/Use Case 중심 URI를 사용하고 동사를 남용하지 않는다.
- Query와 Command를 분리한다.
- Command는 Idempotency·Expected Version·Reason·Operation을 정의한다.
- 비동기 수락은 Operation 조회 URI와 상태를 반환한다.
- 오류는 표준 분류·코드·사용자 메시지·Trace·Retry 가능 여부를 제공한다.
- Paging·Sorting·Filtering은 허용 Field와 Default를 명시한다.
- OpenAPI Operation ID는 안정적이며 Generated Client의 정본이다.

### 허용 예

```text
POST /payments                  지급 신청 생성
GET  /payments/{id}             지급 상세
POST /payments/{id}/cancel      상태 전이 Command
GET  /operations/{operationId}  비동기 결과 조회
```

### 금지 예

```text
POST /executeSql
POST /updateStatus?value=COMPLETED
GET  /retryEverything
```

## 6. Transaction·동시성·멱등성 표준

1. 상태를 조회하고 Permission·Scope·Expected Version을 검증한다.
2. Idempotency Key와 Request Hash를 원자적으로 획득한다.
3. 업무 원장·지원 원장·Audit를 한 Transaction으로 Commit한다.
4. 외부 효과는 Outbox/Attempt/Transfer Ledger로 분리한다.
5. Timeout 뒤 결과 가능성이 있으면 UNKNOWN_RESULT로 유지한다.
6. 다중 Worker는 Lease+Fencing을 사용한다.
7. Partial Success는 Target별 결과를 보존하고 성공 Target을 반복하지 않는다.

## 7. Messaging 표준

- Provider-neutral Envelope와 Reliability Ledger를 사용한다.
- Message ID는 재전송에도 유지한다.
- Producer는 Outbox, Consumer는 Inbox/Dedup을 사용한다.
- Ordering Key·Partition/Queue·Concurrency를 업무 의미와 연결한다.
- Schema/Version 불일치는 Quarantine/DLQ로 분리한다.
- Replay는 원인 수정·범위·승인·Audit 후 수행한다.
- Provider SDK는 Leaf Starter/Adapter 밖에서 참조하지 않는다.

## 9. Security 표준

- 인증 없는 Default Allow를 금지한다.
- Frontend Button 숨김만으로 Authorization하지 않는다.
- Permission·Data Scope를 Query·Command·Export에 적용한다.
- Password/Token/Private Key/Session/Cookie/PII를 Log하지 않는다.
- Secret Rotation은 신규→공존→Consumer 전환→이전 폐기 순서다.
- TLS Hostname/Certificate/Protocol을 검증한다.
- SSRF는 DNS 해석 전후 Allowlist와 Private/Metadata 주소를 차단한다.
- 위험 조치는 Reason·Approval·Expected Version·Audit가 필요하다.

## 11. Frontend 표준

- Route·Menu·Component·Generated Client·Backend Permission을 자동 대조한다.
- Loading·Empty·Error·Permission Denied·Stale·Partial 상태를 구분한다.
- 검색 Default·Timezone·Paging·Sorting을 화면에 표시한다.

## 14. Java 구현 예제

### 14.1 허용되는 Application 경계

```java
@Transactional
public OperationResult execute(Command command, CpfExecutionContext context) {
    idempotency.acquire(command.idempotencyKey(), command.requestHash());
    Aggregate aggregate = repository.findRequired(command.id());
    aggregate.apply(command, command.expectedVersion());
    repository.save(aggregate);
    outbox.append(aggregate.toEvent(context));
    audit.append(AuditRecord.from(command, context, aggregate));
    return OperationResult.accepted(command.operationId(), aggregate.version());
}
```

### 14.2 금지되는 Controller

```java
@PostMapping("/force")
public void force(@RequestParam String sql) {
    jdbcTemplate.execute(sql);
}
```

Controller의 직접 SQL, 상태 강제 변경, 무제한 Retry, Runtime Exception 문자열 판정을 금지한다.

## 15. Error·Retry 구현 표준

- 오류는 Domain/Validation/Auth/Conflict/Dependency/Unknown/Partial로 분류한다.
- Retryable은 오류 유형·HTTP/Reason Code·Idempotency·시도 한도·Deadline을 모두 만족해야 한다.
- 지수 Backoff와 Jitter를 사용하되 전체 Deadline을 넘지 않는다.
- Side Effect 가능 Timeout은 자동 Retry하지 않고 결과 조회를 사용한다.
- Retry exhausted는 DLQ/FAILED_FINAL/UNKNOWN_RESULT 중 정확한 상태로 전환한다.

## 17. SQL·Mapper 작성 표준

- `SELECT *`를 Public Query에 사용하지 않는다.
- Paging은 결정적 Sort와 PK Tie-breaker를 사용한다.
- Update/Delete는 Owner·Status·Version·Scope 조건을 포함한다.
- 동적 SQL Field/Order By는 Allowlist를 사용한다.
- 대량 IN은 상한·Temp/Stage 전략을 정한다.
- Mapper Result와 DTO Field·Null·Timezone·Decimal Scale을 Contract Test한다.
- 3 Vendor에서 Query 의미와 Error Mapping을 대조한다.
