## 1. 기본 원칙

- Owner와 Consumer를 먼저 정한다.
- Public API·SPI·Internal을 분리한다.
- Query와 Command를 분리한다.
- Provider Type을 Public 계약에 노출하지 않는다.
- 상태 변경에는 Version·Reason·Idempotency·Audit를 사용한다.
- 외부 부작용에는 Attempt와 결과 조회를 둔다.
- Source만 바꾸지 않고 SQL·API·Test·Config·Frontend·문서를 함께 변경한다.

## 2. Java 표준

- Package는 Owner 기준.
- DTO는 불변 Record 우선.
- Validation은 입력 경계와 Domain 불변식으로 분리.
- Exception을 숨기지 않고 Error Taxonomy로 Mapping.
- Clock·ID·Provider는 Test 가능한 Port.
- Thread·Connection·Queue는 상한을 둔다.
- Public API/SPI와 중요 복구 로직에 한글 JavaDoc.

## 3. Transaction 표준

- 같은 DB 업무 Row·History·Audit·Outbox는 같은 Transaction.
- Remote 호출을 Local Transaction으로 확장하지 않는다.
- 외부 결과는 Attempt·Idempotency·Reconcile로 연결.
- Retry 대상 Exception과 한도를 명시.
- Version 충돌을 덮어쓰지 않는다.

## 4. SQL 표준

- Query ID와 Consumer를 연결.
- 안정된 Sort·Cursor.
- 영향 건수 검증.
- 3 Vendor 논리 동등성.
- Index 목적과 실행계획.
- Migration·Verify·Rollback/Forward Recovery.
- Secret·PII를 Script에 넣지 않는다.

## 5. API 표준

- Operation ID 고유.
- Request·Response·Error Schema.
- Idempotency Header와 Version.
- 기준시각·Owner·Trace.
- Export 별도 Operation.
- OpenAPI와 Generated Client 일치.

## 6. Frontend 표준

- Raw URL 금지, Generated Client 사용.
- Loading·Empty·Validation·Forbidden·Timeout 분리.
- Button 조건에 상태·Permission·Version·Reason·Approval.
- UNKNOWN·PARTIAL·NACK·DRIFT를 숨기지 않는다.
- Keyboard·Label·ARIA·Responsive 확인.

## 7. Security 표준

- User·Service Identity 분리.
- Audience·Scope·Data Scope.
- Masking·Unmask Reason.
- Secret Reference와 Rotation.
- MFA·Session·Break-glass.
- Negative Test와 Audit.

## 8. Test 표준

| Test | 목적 |
|---|---|
| Unit | Domain 불변식·경계값 |
| Contract | Local·Remote·Provider 동등성 |
| Integration | DB·Broker·HTTP·File 연결 |
| Fault | Kill·Timeout·Response loss·Partial |
| Browser | Route·Field·Button·Permission·Recovery |
| Migration | Fresh·Upgrade·Rollback·Drift |
| Restore | Backup 복구와 업무 대사 |

## 9. Review 표준

Reviewer는 다음을 질문한다.

1. 실제 Consumer가 있는가?
2. 상태 Owner가 명확한가?
3. 중복·동시성·응답 유실을 다루는가?
4. 정상 결과를 API·DB·Log·Audit에서 판정하는가?
5. 실패 뒤 복구와 Rollback이 있는가?
6. Source·SQL·API·Test·문서가 일치하는가?

## 10. 문서 표준

- 초보자 용어와 학습 순서.
- 실제 명령·입력·정상 결과.
- Source·Config·SQL·화면 위치.
- 오류 재현과 복구.
- 고객 변경 영역과 CPF 보호 영역.
- 반복 문구 대신 기능 고유 설명.
- 실제 화면이 없으면 설계 도식임을 명시.

## 11. Release 표준

- Source SHA·Version·Manifest.
- Checksum·Signature·SBOM·Provenance.
- DB·Config·Secret·Restart 영향.
- Canary·중단 기준·LKG.
- Test 환경·명령·Exit Code·Report Hash.
- 미실행 Runtime을 성공으로 기록하지 않는다.

## 12. 금지 패턴

- Provider SDK Type의 Public 노출.
- 동일 상태의 이중 Owner.
- ADM/BZA의 DB 직접 갱신.
- 화면 숨김만으로 API 권한 대체.
- 비멱등 Write Blind Retry.
- Log의 Secret·Raw PII.
- Wildcard 운영 삭제.
- 실행하지 않은 Test 성공 기록.
- Route 이름만 바꾼 반복 문서.
