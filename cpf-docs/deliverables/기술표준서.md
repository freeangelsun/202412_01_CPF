## 1. 표준 적용 범위

Java, Spring, API, SQL, 보안, Logging, Test, Build, 문서와 예외 승인 규칙을 정의한다. 별도 개발코딩표준서는 만들지 않으며 이 문서의 개발·코딩 표준 장을 정본으로 사용한다.

## 2. Java·Package 표준

- Java 25 문법과 Toolchain을 사용한다.
- Public API/SPI/Internal 경계를 Package와 Build Dependency로 검증한다.
- `*` import, 한 줄 압축 Class, 전역 Mutable State, 시스템 현재시각 직접 호출을 금지한다.
- 시간은 주입 가능한 `Clock`, 식별자는 표준 Generator, Random은 목적별 Provider를 사용한다.
- Optional은 반환 경계에서만 제한적으로 사용하고 Entity/DTO Field에 남용하지 않는다.
- Exception은 Validation, Conflict, Dependency, Timeout, Unknown Result로 분류한다.

## 3. Module·Starter 표준

- 공개 선택면: 6 Profile
- 내부 분류: 7 Capability Group
- 신규 Starter는 Value Contract, Public API, Extension SPI 또는 N/A 근거, 실제 Consumer, 제거 대안 비교, Footprint, Runtime Evidence 계획을 갖춘다.
- Profile은 내부 Leaf를 전이 조립하고 `resolved-starter-lock.json`으로 결과를 고정한다.
- 상호 배타 Provider를 동시에 Default로 등록하지 않는다.
- Legacy Artifact ID는 Catalog의 `legacyArtifactIds`에서만 Migration 용도로 관리한다.

## 4. API 설계 표준

1. URI는 Resource와 업무 행위를 구분한다.
2. 상태 변경에는 Idempotency Key와 Expected Version을 적용한다.
3. 표준 Header에는 Transaction, Trace, Actor, Tenant, Request Time을 포함한다.
4. API 응답은 상태, 결과 Code, Message, Tracking ID를 포함한다.
5. 위험 조치는 Preview와 Apply를 분리한다.
6. Export는 비동기 Job으로 처리하고 Download 권한과 만료를 적용한다.
7. OpenAPI Operation ID는 Frontend Generated Client와 1:1로 유지한다.

## 5. Transaction·동시성 표준

- Transaction 경계는 Application Service가 소유한다.
- 외부 호출을 DB Transaction 내부에서 장시간 대기하지 않는다.
- 낙관적 Lock은 `expectedVersion`으로 검증한다.
- Worker Claim은 Lease와 Fencing Token을 함께 사용한다.
- 동일 멱등성 Key의 병렬 요청은 한 건만 부작용을 수행한다.
- Timeout 후 결과가 불명확하면 `UNKNOWN`으로 저장하고 Reconcile 전 재실행하지 않는다.

## 6. Messaging 표준

- 업무 Source는 Provider SDK가 아니라 `CpfBrokerClient`와 CPF DTO를 사용한다.
- Topic/Queue는 Binding Name으로 간접 참조한다.
- Outbox/Inbox/DLQ 상태, Attempt, Lease, Next Retry Time, Last Error를 보존한다.
- Consumer는 처리 완료 전 ACK하지 않는다.
- Poison Message는 무한 Retry하지 않고 DLQ와 운영 조치로 전환한다.

## 7. File·외부 연계 표준

- 파일명과 원격 경로를 신뢰하지 않고 Allowlist Path Policy를 적용한다.
- Checksum, Size, Count, MIME/Extension, Archive Entry Limit을 검증한다.
- SFTP Host Key Pinning과 Secret Provider를 사용한다.
- HTTP/TCP 전문은 Correlation ID와 Timeout Budget을 가진다.
- Fixed-length/ISO8583 Layout은 Version과 Charset을 고정한다.
- 응답 유실 시 원 거래 조회나 Reversal/Reconcile 절차를 갖춘다.

## 8. 보안 표준

| 영역 | 필수 통제 |
|---|---|
| 인증 | Issuer/Audience/Expiry/Signature 또는 Session 검증 |
| 인가 | Permission + Data Scope + Resource 조건 |
| 조치 | Reason + Approval + Expected Version |
| Secret | 외부 Secret Provider, 평문 저장 금지 |
| Masking | API/Log/Audit/Export 일관 적용 |
| 감사 | Actor, Approver, Before/After, Result, Correlation |
| SSRF | Scheme/Host/Port/CIDR Allowlist |
| TLS | 인증서 검증, 만료·교체 Runbook |

## 9. Logging·Metric·Trace 표준

- Log에는 Transaction ID, Trace ID, Segment ID, Attempt, Module, Operation, Result Code를 구조화한다.
- 개인정보·Credential·Token·전문 원문을 기본 Log에 기록하지 않는다.
- Metric은 성공/실패/UNKNOWN, Latency, Retry, DLQ, Lease Reclaim, Queue Depth를 분리한다.
- Trace는 외부 호출과 비동기 경계를 연결하되 Payload 전체를 Attribute로 저장하지 않는다.
- 동적 Log Level과 Trace Sampling 변경은 ADM Preview/Approval/Audit를 거친다.

## 10. SQL·DB 표준

- 공식 Vendor: Oracle, PostgreSQL, MariaDB
- 동일 논리 객체와 Query ID를 유지하고 Vendor 차이는 전용 Pack에서 관리한다.
- 모든 변경은 Install/Migration/Rollback/Verify/Checksum을 제공한다.
- DDL에 PK, Audit Column, 상태, Version, 시간대 정책을 명시한다.
- 대량 조회는 Pagination/Cursor/Streaming을 사용한다.
- `SELECT *`, 무조건 Full Scan, 문자열 SQL 조립을 금지한다.

## 11. Test 표준

| Test | 필수 대상 |
|---|---|
| Unit | 순수 규칙, Validation, 상태 전이 |
| Contract | Public API/SPI와 Provider Conformance |
| Integration | DB, Broker, File, 외부 Adapter |
| Fault | Timeout, ACK 유실, Process Kill, Partial Apply |
| Multi-instance | Lease, Fencing, Rebalance, Failover |
| Browser | ADM/BZA Route, 권한, 위험 조치, 접근성 |
| Supply Chain | SBOM, License, Hash, Publication |

직접 실행하지 않은 Test는 성공으로 기록하지 않는다.

## 12. Build·CI 표준

```powershell
./gradlew.bat clean test assemble qualityGate --no-daemon --max-workers=1 --stacktrace
./gradlew.bat publishCpfStagingPlatformArtifacts --no-daemon
```

`.github/workflows/cpf-qa39-final-required.yml`의 모든 Job이 성공해야 Release Candidate로 승격할 수 있다. Self-hosted DB/Runtime Runner가 없으면 해당 Job은 `미검증`이며 성공으로 대체하지 않는다.

## 13. 코드 리뷰 Checklist

- Owner Module과 Consumer가 명시됐는가?
- Public API/SPI/Internal 경계가 유지되는가?
- Provider OSS 타입이 Public API에 노출되지 않는가?
- 정상·오류·경계·동시성·UNKNOWN·복구가 Test에 있는가?
- Secret·Masking·Audit가 검토됐는가?
- 3 Vendor DB 영향이 정렬됐는가?
- Generator, Catalog, BOM, Manifest가 함께 변경됐는가?
- 임시 파일·Build Output·Stale Evidence가 없는가?

## 14. 예외 승인

Generated Domain의 수동 설정 예외는 `cpf-approved-exceptions.csv`와 Runtime Policy File에 등록한다. 예외에는 Owner, 대상, 이유, 범위, 시작/만료, Artifact Version, Config Hash, 승인자를 기록한다. 미등록·만료·Hash 불일치는 Fail-closed한다.
