## 1. 표준 적용 우선순위

실제 Source·SQL·API·Config·Frontend·Script·Test → Architecture·Specification → 공식 매뉴얼 순서다. 충돌 시 Owner와 Consumer를 기준으로 정본을 하나로 정리한다.

## 2. Java

- Java 25 Toolchain 사용
- 한 Class 한 책임과 명시적 상태 전이
- `Clock`, ID Generator, Random Provider 주입
- 전역 Mutable State 금지
- `*` import와 한 줄 압축 Class 금지
- Exception을 Validation·Conflict·Timeout·Dependency·Unknown Result로 분류
- Public API/SPI와 복구·동시성·보안 로직에 JavaDoc 작성

## 3. Package·Module

- Public API: `.api`
- Extension SPI: `.spi`
- Internal: `.internal`
- Core의 상위 Module 역참조 금지
- Domain 간 DB 직접 접근 금지
- Consumer 없는 Interface·Starter 금지
- Profile과 내부 Provider 중복 직접 선언 금지
- Generated Output 수동 편집 금지

## 4. API

1. Resource와 Action을 구분한다.
2. 입력 Type·길이·형식·기본값·범위를 OpenAPI에 명시한다.
3. 상태 변경에는 Idempotency Key와 Expected Version을 적용한다.
4. 위험 조치는 Preview와 Apply를 분리한다.
5. 비동기 작업은 Operation ID와 상태 조회를 제공한다.
6. Export는 비동기 Job과 Download 만료·권한을 적용한다.
7. Operation ID는 Generated Client·Route와 1:1로 유지한다.

## 5. Transaction·동시성

- Transaction 경계는 Application Service 소유
- 외부 호출을 DB Transaction 안에서 장시간 대기 금지
- 낙관적 Lock은 Expected Version 사용
- 동일 멱등성 Key 병렬 요청은 부작용 한 건
- Worker Claim은 Lease와 Fencing Token
- Timeout 후 결과 불명은 UNKNOWN 보존
- Partial Apply는 Target별 결과 보존

## 6. Messaging

- 업무 Source는 CPF Broker API 사용
- Topic/Queue는 Binding Name으로 간접 참조
- Outbox/Inbox/DLQ에 Attempt·Lease·Next Retry·Error 보존
- 처리 완료 전 ACK 금지
- Poison Message 무한 Retry 금지
- ACK 유실은 Reconcile 전 재발행 금지

## 7. File·외부 연계

- Path·File Name·Target URL 신뢰 금지
- Allowlist와 Canonicalization 적용
- File Size·Count·MIME·Checksum·Archive Limit 검증
- SFTP Host Key Pinning
- HTTP/TCP Timeout Budget과 Correlation
- 전문 Layout Version과 Charset 고정
- 응답 유실 시 원 거래 조회·Reversal·Reconcile

## 8. Security

| 영역 | 표준 |
|---|---|
| 인증 | Issuer·Audience·Signature·Expiry 또는 Session 검증 |
| 인가 | Permission + Data Scope + Resource Condition |
| 위험 조치 | Reason + Approval + Expected Version |
| Secret | 외부 Provider Reference |
| Masking | API·화면·Log·Trace·Audit·Export 일관 적용 |
| Audit | Actor·Approver·Before/After·Reason·Result |
| SSRF | Scheme·Host·Port·CIDR Allowlist |
| TLS | Chain·SAN·Expiry 검증과 Rotate Runbook |
| Break-glass | Scope·Expiry·Review |

## 9. Logging·Metric·Trace

Log에는 Transaction ID, Trace ID, Segment, Attempt, Module, Operation, Result Code를 구조화한다. Token·Credential·개인정보·전문 원문을 기록하지 않는다.

Metric은 성공·실패·UNKNOWN, Latency, Retry, Circuit, DLQ, Lease Reclaim, Queue Depth를 분리한다.

## 10. SQL·DB

- Oracle·PostgreSQL·MariaDB 논리 동등성
- Bind Variable과 안정적 Pagination
- `SELECT *`, 문자열 SQL 조립 금지
- Update/Delete 영향 Row Count 검증
- Install·Migration·Rollback·Verify·Checksum
- Drift 발견 시 임의 DDL 금지
- 대량 Table Retention·Archive·Purge 절차

## 11. Frontend

- Route Registry와 OpenAPI Generated Client 정합
- Menu·Button·API Permission 분리
- 조회 전용 화면에 가상 변경 조치 금지
- 상태 변경은 Reason·Expected Version·Approval 입력
- Timeout 후 Operation 조회
- Partial Apply Target별 표시
- Chromium·Firefox·WebKit과 접근성 Test

## 12. Test

| Test | 확인 |
|---|---|
| Unit | 규칙·Validation·상태 |
| Contract | Public API/SPI·Provider |
| Integration | DB·Broker·File·Adapter |
| Fault | Timeout·Response/ACK Loss·Process Kill |
| Concurrency | Idempotency·Version·Lease/Fencing |
| Multi-instance | Rebalance·Failover·Stale Writer |
| Browser | Route·권한·Approval·Session |
| Supply Chain | Hash·SBOM·License·Publication |

직접 실행하지 않은 Test를 성공으로 기록하지 않는다.

## 13. Build·Publication

```powershell
./gradlew.bat clean test assemble qualityGate --no-daemon --max-workers=1 --stacktrace
./gradlew.bat publishCpfStagingPlatformArtifacts --no-daemon
```

Artifact Mode은 LOCAL_DEV, REMOTE, OFFLINE 중 하나를 사용한다. Credential을 Command Line과 Log에 노출하지 않는다.

## 14. Code Review

Owner·Consumer, Public 경계, 정상·오류·동시성·UNKNOWN·복구, Security·Audit, 3 Vendor, Generator·Catalog·BOM·Manifest, OpenAPI·Frontend, 임시 파일·Secret을 검토한다.

## 15. 문서

고객 기능 장에는 결과, 선택 기준, 준비값, 절차, 입력, 정상 결과, 실패, 복구, 관측, 교육, 운영 인계를 포함한다. Source에 없는 API·화면·Permission·상태를 만들지 않는다.
