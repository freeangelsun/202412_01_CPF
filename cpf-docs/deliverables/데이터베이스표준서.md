## 1. Ownership·Schema 원칙

- 업무 테이블은 단일 Domain Owner가 소유한다.
- 다른 Domain은 Owner API/Event/Read Model을 사용하고 직접 DML·Join을 금지한다.
- 지원 원장(Idempotency/Outbox/Inbox/Attempt/Transfer/Notification/Batch)은 해당 기술 Owner가 소유한다.
- ADM/BZA/Gateway는 다른 Owner 테이블을 직접 수정하지 않는다.
- 3 Vendor는 같은 Logical Contract·상태·Constraint·Index 의미를 유지한다.

## 2. Naming

| Sequence | sq_<table> | sq_pay_payment |
| Column | snake_case, 의미 중심 | expected_version |

## 5. Key·Constraint 표준

- PK는 변경되지 않는 기술 식별자를 사용한다.
- 업무 Key는 Unique Constraint와 유효 범위를 명시한다.
- FK는 Owner 내부에서 사용하고 Domain 간 FK는 금지한다.
- 상태는 Check 또는 기준 코드와 Application 상태 전이 Test를 함께 둔다.
- 금액·수량·기간의 음수/범위를 DB와 Application 양쪽에서 보호한다.
- Nullable은 “미입력/미결정/해당없음” 의미를 구분한다.
- Logical Delete 뒤 Idempotency Replay와 Unique Key 재사용 정책을 명시한다.

## 6. Index 표준

| 조회 | Index 설계 | 금지 |
|---|---|---|
| PK 상세 | PK | 중복 보조 Index |
| 업무 Key | Unique 또는 Leading Index | 함수 변환으로 Index 무효 |
| 상태+기간 | 선택도와 정렬 순서 | 상태 단독 저선택도 남발 |
| Cursor Paging | 정렬 Column+PK | Offset 대용량 남용 |
| 미처리 Outbox | status+next_attempt_at+id | 무제한 Full Scan |
| Lease Claim | status+lease_until+id | Fencing 없는 Update |
| Audit 기간 | occurred_at+actor/target | PII 원문 Index |
| 배치 대상 | business_date+status+pk | 비결정적 정렬 |

Execution Plan·Cardinality·Index Size·Write Cost를 함께 검토한다. Hint는 Vendor별 최후 수단이며 근거와 제거 조건을 기록한다.

## 7. Transaction·Lock·Concurrency

- Application Use Case가 Transaction 경계를 소유한다.
- 원격 호출·파일 전송·Broker ACK를 긴 DB Transaction 안에서 기다리지 않는다.
- Optimistic Lock은 `version`을 WHERE에 포함하고 0 Row면 Conflict로 처리한다.
- Pessimistic Lock은 범위·순서·Timeout을 정하고 Deadlock Retry를 제한한다.
- Lease Claim은 Owner·Expiry·Fencing Token을 원자적으로 변경한다.
- 대량 Update는 Batch Size·Commit·Checkpoint·Audit를 정한다.
- Serializable/Isolation 강화는 성능·Deadlock Test와 함께 승인한다.

## 9. Migration 표준

1. Canonical Metadata와 Logical Change를 작성한다.
2. MariaDB·PostgreSQL·Oracle Migration과 Rollback/Forward Fix를 생성한다.
3. Fresh Install을 빈 DB에서 실행한다.
4. 지원 이전 Version별 Upgrade를 실행한다.
5. 중단 후 재실행과 일부 적용을 시험한다.
6. 이전/신규 Application 공존을 시험한다.
7. Schema Hash·Constraint·Index·초기 데이터·대사 Query를 비교한다.
8. Backup Restore 뒤 재적용을 시험한다.

### Expand·Migrate·Contract

- Expand: Nullable Column/Table/Index를 추가해 구·신 Version이 공존한다.
- Migrate: Backfill을 Checkpoint·대사 가능하게 실행한다.
- Switch: 신 Version이 새 구조를 사용한다.
- Contract: 구 Version 제거와 보존기간 뒤 구 구조를 제거한다.

### 9.1 Schema Drift

정본 Migration과 실제 Schema의 Table·Column·Type·Nullability·Default·Constraint·Index·Sequence·Trigger 차이를 비교한다. Drift가 있으면 운영 DB에서 수동 DDL로 맞추지 않고 원인 변경을 Migration으로 정본화한 뒤 Verify·Upgrade·Rollback/Forward Fix·Reapply를 다시 수행한다.

## 10. Rollback·Forward Fix

| 변경 | Rollback | Forward Fix |
|---|---|---|
| 신규 Index | Drop 가능 | Index 수정/재생성 |
| Nullable Column | 사용 전 Drop 가능 | Default/Backfill |
| Non-null Column | Backup/공존 필요 | Nullable→Backfill→Constraint |
| Column Rename | View/Dual Write 필요 | 새 Column 복사 |
| Data 변환 | 원본 보존/Backup | 보정 Migration |
| Table Drop | Backup Restore 외 위험 | Archive→지연 Drop |
| Message/DB 동시 변경 | Application만 Rollback 금지 가능 | 호환 Adapter/Forward Migration |

## 11. 대용량·Batch SQL

- PK/Cursor 기반으로 읽고 결정적 정렬을 사용한다.
- Chunk별 건수·금액·Hash와 Checkpoint를 저장한다.
- Update는 대상 Version/Status 조건을 포함한다.
- Skip/오류 Row는 별도 오류 원장에 남긴다.
- Partition 범위는 겹치지 않고 전체를 덮는다.
- Restart는 완료 Chunk/Partition을 반복하지 않는다.
- Statistics·Vacuum/Analyze·Tablespace/Undo/Redo 영향은 Vendor별로 확인한다.

## 12. Security·Masking·Audit

- Runtime 계정은 Owner Schema 최소 DML만 가진다.
- Migration/Admin/Runtime 계정을 분리한다.
- Credential은 Secret Provider에서 공급한다.
- 민감 Column은 암호화·Tokenization·Masking·접근 Audit를 적용한다.
- 운영 Query와 Export는 Data Scope와 Reason을 적용한다.
- Audit Table은 일반 업무 DML로 수정하지 못하게 한다.

## 13. Backup·Restore·DR

- RPO/RTO·Backup 범위·암호화·보존·Offsite를 정의한다.
- Full/Incremental/Log/PITR 조합을 시험한다.
- Restore 환경에서 Schema Version·건수·금액·Hash·Outbox/Inbox·권한을 대사한다.
- DR 전환은 Single Writer·Replication Position·Sequence/ID·Broker·외부 결과를 확인한다.
- Failback은 별도 승인과 대사 후 수행한다.

## 15. Vendor별 구현 주의사항

### 15.1 MariaDB

- `utf8mb4` Charset/Collation을 명시하고 대소문자·정렬 의미를 확인한다.
- Online DDL 지원·Table Copy·Metadata Lock 시간을 검토한다.
- `AUTO_INCREMENT`를 외부 업무 ID로 노출하지 않는다.
- `timestamp`와 Session Timezone 변환을 확인한다.
- JSON Index는 Generated Column/지원 기능과 호환성을 검토한다.

### 15.2 PostgreSQL

- `timestamptz`와 `timestamp` 선택을 명확히 한다.
- `jsonb`, Partial/Expression Index 사용 시 다른 Vendor 대체 계약을 둔다.
- `CREATE INDEX CONCURRENTLY`는 Transaction/실패 상태를 별도 관리한다.
- Vacuum/Analyze·Bloat·Long Transaction을 운영 지표로 관리한다.
- Sequence/Identity Cache와 DR 전환을 확인한다.

### 15.3 Oracle

- `DATE`가 시간까지 포함함을 고려하고 Timestamp Type을 명시한다.
- 빈 문자열이 NULL로 취급되는 차이를 Contract Test한다.
- Identifier 길이·CLOB/BLOB·Sequence·Tablespace/Undo/Redo를 계획한다.
- Online Redefinition/Index 작업의 License·운영 정책을 확인한다.
- Numeric Precision과 Boolean Mapping을 Check Constraint로 보호한다.

## 17. Migration 예시 양식

```sql
-- owner: PAY
-- purpose: payment status index
-- compatibility: old/new application coexist
-- precheck: duplicate business key = 0
CREATE INDEX ix_pay_payment__status_created_at
    ON pay_payment (status, created_at, id);
-- postcheck: query plan uses index for approved range scan
```

실제 문법은 Vendor Pack별로 작성하고 Canonical Metadata와 자동 대조한다.

## 18. Optimistic Update 예시

```sql
UPDATE pay_payment
   SET status = :next_status,
       version = version + 1,
       updated_at = :now,
       updated_by = :actor
 WHERE id = :id
   AND status = :current_status
   AND version = :expected_version;
```

영향 Row가 0이면 Not Found·Permission Scope·State Conflict·Version Conflict를 조회 결과로 구분한다. 무조건 재시도하지 않는다.

## 19. Lease Claim Logical SQL

1. `status=READY`이고 Lease가 없거나 만료된 대상을 제한 개수로 선택한다.
2. Owner·Lease Until·Fencing Token 증가를 원자적으로 적용한다.
3. Update 결과를 Worker에 반환한다.
4. Worker Write는 현재 Fencing Token을 조건에 포함한다.
5. Lease 연장과 완료가 동일 Owner/Token인지 확인한다.

Vendor별 `SKIP LOCKED`, Returning/Output, Lock 문법 차이는 Adapter에서 흡수하고 외부 의미는 같게 한다.

## 22. DB 장애 Runbook

### 연결 고갈
1. Application Pool과 DB Session을 대조한다.
2. Long/Idle Transaction과 Leak를 찾는다.
3. 신규 요청 제한·Instance 격리를 적용한다.
4. Pool을 무조건 늘리기 전에 원인을 수정한다.

### Deadlock
1. Deadlock Graph·SQL·Lock 순서를 확보한다.
2. 업무 결과 Commit 여부를 확인한다.
3. Retryable Transaction만 같은 Idempotency Key로 제한 재시도한다.
4. Lock 순서·Index·Transaction 범위를 수정한다.

### Disk/Undo/Log Full
1. 업무/Backup/Temp/Log 소유 데이터를 구분한다.
2. 임의 파일 삭제를 금지한다.
3. 쓰기 제한·용량 확장·Archive를 수행한다.
4. 중단 Transaction·Migration·Batch를 대사한다.

### Replication/DR 지연
1. Replication Position·Lag·Error를 확인한다.
2. RPO 초과 시 Failover를 중단하거나 승인한다.
3. Single Writer를 Fencing하고 Sequence·Outbox를 대사한다.
