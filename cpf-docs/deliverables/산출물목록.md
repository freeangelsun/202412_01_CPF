## 19. 운영 Evidence

운영 변경은 가능한 범위에서 다음 Evidence를 연결한다.

```text
requester / reason / approval
 -> operationId / idempotencyKey / expectedVersion
 -> target snapshot
 -> attempt / apply result
 -> observed state / ACK-NACK
 -> audit
 -> rollback or reconcile decision
```

Screenshot만으로 상태 변경 성공을 판정하지 않는다.

## 21. 문서 수용 Gate

문서 변경은 다음 Gate를 각각 확인한다.

1. **Scope Gate**: 허용된 공식 문서 구조를 벗어나지 않았는가.
2. **Source Gate**: Class/API/SQL/Config/Frontend/Test와 일치하는가.
3. **Coverage Gate**: Starter/EDU/Route/Property/Tool 누락이 없는가.
4. **Task Gate**: 독자가 절차와 정상화 기준을 찾을 수 있는가.
5. **Failure Gate**: Timeout/응답 유실/Partial/Unknown/Recovery가 있는가.
6. **Security Gate**: Permission/Masking/Secret/Reason/Approval/Audit가 있는가.
7. **Static Quality Gate**: Link/Anchor/Table/Forbidden phrase/Encoding/Whitespace를 점검했는가.
8. **Render Gate**: 배포 포맷으로 변환할 경우 clipping/blank/overlap을 확인했는가.
9. **Runtime Gate**: 실제로 실행한 Test만 성공으로 기록했는가.

## 22. 패키지 포함·제외 기준

최종 문서 ZIP에는 요청 범위의 신규/수정 최종 파일과 해당 Evidence만 넣는다. 다음은 넣지 않는다.

- `.git`, IDE metadata.
- `build`, `node_modules`, compiled classes.
- log/tmp/bak/patch.
- 렌더 QA용 중간 PNG/DOCX/PDF(사용자가 공식 binary deliverable을 요청하지 않은 경우).
- Secret/Token/Password/개인정보 원문.
- 과거 Revision 중복본.

## 23. 삭제 Manifest

삭제가 필요한 경우 exact repo-relative path와 이유를 Manifest에 기록한다. Wildcard, `git clean`, 전체 untracked 삭제는 사용하지 않는다. 이번 문서 패키지에서 기존 Repository 파일 삭제를 요구하지 않는 경우 `DELETE_MANIFEST.txt`에 0건으로 명시한다.

## 24. 적용·Rollback 산출물

적용은 Repository Root에서 ZIP을 풀어 상대경로대로 복사하는 것을 기준으로 한다. Rollback은 **이번 ZIP이 추가/수정한 정확한 경로**만 원복/삭제한다. 기존 PDF/DOCX나 다른 작업자의 변경을 광범위하게 삭제하지 않는다.
