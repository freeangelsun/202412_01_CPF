### 3.1 출력 위치와 소비자

각 산출물은 Repository Root 상대경로, 생성 도구, 출력 형식, 실제 Consumer와 Release 포함 여부를 기록한다. 생성 결과가 임시 디렉터리나 개인 경로에만 남으면 정식 산출물로 인계하지 않는다.

## 5. 산출물 생명주기

1. 요구 ID와 Owner를 정한다.
2. Source/API/SQL/Config/Frontend/Test 변경 범위를 작성한다.
3. Generator가 생성하는 산출물과 수동 작성 영역을 구분한다.
4. Draft에서 Technical Review·Security/DB/Operations Review를 수행한다.
5. Build·Contract·Runtime·Fault·Browser 중 적용 Gate를 실행한다.
6. Release Manifest에 Version·Source SHA·Hash·Approval을 고정한다.
7. 배포·운영 인계 후 보존·폐기 시점을 관리한다.
8. Source 변경 시 양방향 Drift Gate로 재생성·현행화한다.

## 7. 문서 완결성 Gate

각 기능 장은 결과, 선택 기준, 준비값, 순서, 입력, 정상 결과, 실패 대응, 복구, 교육, 운영 인계 10개 항목을 모두 갖는다. Class/API/Property 목록만 있거나 “확인한다”로 끝나는 문서는 통과시키지 않는다.

## 13. 재생성·Drift 처리

- OpenAPI↔Generated Client↔Route Contract Drift는 Build를 차단한다.
- Configuration Properties↔Catalog↔Deployment Overlay Drift는 배포를 차단한다.
- Canonical Metadata↔3 Vendor SQL↔Runtime Schema Drift는 Migration을 차단한다.
- Capability Profile↔Generator Manifest↔Build Dependency Drift는 Domain Build를 차단한다.
- Route/Menu/Permission↔Backend Operation Drift는 Frontend Release를 차단한다.
- 문서 식별자↔Source Drift는 공식 문서 Release를 차단한다.

Drift 수정은 생성 결과 수동 편집이 아니라 원본 정본과 Generator를 수정한 뒤 전체를 재생성한다.
