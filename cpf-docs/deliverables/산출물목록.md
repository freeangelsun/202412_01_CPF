## 5. 발견 사항과 개선 요청

### DOC-001 — 기준 Commit 노후화

기존 산출물의 Source 기준이 `e134c1f...`로 남아 최신 `61dcbbe... (04_09)`와 달랐다. 이번 문서에서 기준을 갱신했다.

### DOC-002 — 공식 문서 구조 불일치

문서 표준은 ADM 개발자와 ADM 운영자를 분리하고 Starters·Tools를 역할 매뉴얼에 통합하도록 정의하지만 기존 Guide는 ADM 통합본과 Starters·Tools 독립본이었다. 이번 구조에서 8개 역할 매뉴얼로 재편했다.

### DOC-003 — README 공개 Profile 설명 불일치

기존 README의 `13개 Versioned Capability Profile` 표현은 최신 `settings.gradle`과 Starter Catalog가 강제하는 6개 공개 Profile과 맞지 않았다. 6개 Profile·7개 Capability Group으로 수정했다.

### DOC-004 — 실제 ADM Route 대비 운영 절차 부족

기존 ADM 문서는 일부 대표 Route만 설명했다. 이번 ADM 운영자 매뉴얼에 실제 Route Registry의 주요 운영·배치·Gateway·Security Route와 조치 유형을 확장했다.

### DEV-REQ-001 — V9 FULL_ASSIGNMENT 실행 기록

`FULL_ASSIGNMENT_VALIDATION.json`의 상태가 `NOT_EXECUTED_IN_ARTIFACT_BUILD_ENVIRONMENT`이므로 30,558 Requirement와 40,763 Scenario 전수 Mapping 실행 기록이 필요하다. 이는 기능 미완료 판정이 아니라 개발 관리·QA Evidence 요청이다.

### DEV-REQ-002 — 초기화 Script 명칭 정합

문서 안내의 `initialize-devgpt-control-v9.ps1`과 실제 `initialize-development-management.ps1` 명칭 차이를 하나의 정본 이름과 Compatibility Wrapper로 정리해야 한다.

### QA-REQ-001 — CI/Workflow 상태 기록

`04_09` Commit에 Combined Status와 Workflow Run이 없었던 인수인계 사실을 QA 기록에 유지한다. Release 판단 시 Required Workflow 실행 결과를 연결한다.

### QA-REQ-002 — 고객 환경 Runtime 기록

이 문서 작성 세션은 Java·3 DB·Broker·Browser·다중 인스턴스·Fault Runtime을 재실행하지 않았다. 고객 배포 승인에서는 실행 환경·명령·Exit Code·Artifact Hash를 별도 Evidence로 보존한다.
