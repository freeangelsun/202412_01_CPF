## 1. 제품 정의와 현재 판정

CPF의 정식 명칭은 **Core Platform Framework**다. CPF는 공통 Library나 Sample 묶음이 아니라 시스템을 설계·개발·실행·운영·감사·확장·설치·Upgrade·Rollback하는 Business Platform 품질의 상용 Framework를 목표로 한다.

### 1.1 제품 범위

- Modular Monolith와 MSA
- 동일 JVM Local Adapter와 분리 WAS Remote Adapter
- 다중 인스턴스·부분 실패·재시도·Circuit Breaker
- 인증·권한·사유·승인·감사·마스킹
- Transaction·멱등성·Outbox/Inbox·UNKNOWN_RESULT·대사
- Kafka·외부 API·File·Attachment·Archive·Shell
- Spring Batch·Scheduler·Worker·Center-Cut·Host Agent
- ADM Control Plane과 선택형 BZA·Gateway
- Generator·DB Vendor Pack·Migration·Rollback
- OpenAPI·JavaDoc·EDU·Test·Evidence·Supply-chain

## 4. 실행 Topology

### 4.1 Modular Monolith

같은 JVM에서는 Public API를 구현하는 Local Adapter를 사용한다. 호출자는 구현 Bean이나 다른 Owner DB에 직접 결합하지 않는다. Transaction은 변경 Owner의 Application Service가 소유한다.

### 4.2 MSA·분리 WAS

Remote Adapter는 같은 계약을 HTTP·Kafka 등 승인된 Transport로 변환하며 다음 의미를 보존한다.

- `transactionId`, `traceparent`, `operationId`, `idempotencyKey`
- Subject·Role·Permission·Data Scope
- Timeout Budget와 Deadline
- 표준 오류 Code와 Retry 가능 여부
- 요청 Hash·Attempt·상대 결과 확정 방법

### 4.3 다중 인스턴스

- Registry 상태만으로 Owner를 가정하지 않는다.
- Lease·Claim·Fencing Token·Expected Version을 사용한다.
- Drain은 신규 할당을 차단하고 진행 중 처리를 안전하게 종료한다.
- Stale Owner의 늦은 완료는 현재 상태를 덮어쓰지 못한다.
- Partial Apply는 전체 성공으로 축약하지 않는다.

```text

```

`UNKNOWN_RESULT`를 일반 실패로 바꾸거나 Blind Retry하지 않는다. Idempotency Key, Attempt Ledger, 상대 Status, Outbox/Inbox, DB 상태를 대사해 결과를 확정한다.

## 6. 보안·권한·감사

- 최종 권한 판정은 Server에서 수행한다.
- Menu·Button·API Permission·Data Scope를 분리한다.
- 위험 조치는 사유·승인·Expected Version·Request Hash·만료를 확인한다.
- ADM/BZA Session은 HttpOnly Cookie와 CSRF 경계를 사용한다.
- Secret·Token·Password·원문 개인정보는 Log·Evidence·화면에 노출하지 않는다.
- 원문 조회·다운로드·Break-glass는 별도 권한과 감사가 필요하다.
- 운영 기능 실패가 원 거래를 오염시키지 않도록 Transaction 경계를 분리한다.

## 7. DB·Migration·Release

기준 SHA는 MariaDB·PostgreSQL·Oracle에 다음 Migration과 Rollback을 제공한다.

| Version | 책임 |
|---|---|
| V82/R82 | Spring Batch Primary Control Link |
| V83/R83 | Spring Session JDBC BFF |
| V84/R84 | db-scheduler Primary |
| V85/R85 | BZA Bootstrap Approval |

원칙:

- Flyway OSS Core가 History·Order·Checksum Engine이다.
- Vendor SQL을 단순 문자열 치환으로 완료 처리하지 않는다.
- Fresh Install, N-1 Upgrade, 실패 Migration 복구, Checksum Tamper, Backup/Restore를 Vendor별로 검증한다.
- Artifact는 exact Source SHA·Hash·Signature·SBOM·NOTICE·Vulnerability 결과와 연결한다.
