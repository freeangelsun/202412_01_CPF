## 문서 사용 계약

| 상태 | 의미 |
|---|---|
| `완료` | 최신 exact SHA에서 Source·Consumer·Failure/Recovery·필수 Runtime Evidence가 모두 확인됨 |
| `부분 구현` | 일부 계층만 연결되었거나 Legacy/대체 경로가 Primary로 남음 |
| `미구현` | 제품 Source 또는 필수 수직 연결이 없음 |
| `미검증` | Source는 있으나 필요한 실제 환경 검증이 실행되지 않음 |
| `실패` | 필수 Gate·Scenario가 실패함 |
| `재확인 필요` | Source·Evidence·SHA·환경이 상충하거나 불명확함 |

- **Source-confirmed**: 기준 SHA의 Source·Config·SQL·Route·Script에서 직접 확인했다.
- **Product contract**: CPF 정본이 요구하는 동작이다. 실제 Runtime Evidence가 없으면 `미검증`으로 표시한다.
- **Operator procedure**: 운영자가 수행해야 하는 절차다. 화면·권한·환경 차이는 실제 배포 Catalog를 우선한다.
- **Prohibited**: 성공처럼 보여도 제품 안정성·감사·복구를 깨뜨려 금지하는 방식이다.

```text
Requirement → Owner → Public API/SPI → Application/Policy → Adapter/State
→ Runtime Consumer → Security/Approval/Audit → Failure/Recovery
→ Test/Evidence → Guide/EDU → Legacy 제거
```

## 4. 완결 Reference 기능

Reference는 **승인된 운영 요청을 멱등하게 접수하고, 상태와 Outbox를 저장한 뒤 Kafka Event를 처리하며, 결과 불명 시 대사하는 기능**이다.

```text

→ Validation
→ Permission·Reason
→ Idempotency Key + Request Hash 예약

→ GET /api/v1/operations/{operationId}
```

### 5.2 Application Service

```java
@Service
@RequiredArgsConstructor
public class OperationCommandService implements OperationCommandUseCase {
    private final OperationRepository operations;
    private final IdempotencyRepository idempotency;
    private final OutboxRepository outbox;
    private final PermissionPort permissions;
    private final AuditPort audit;

    @Transactional
    @Override
    public OperationReceipt create(CreateOperationCommand command, CpfExecutionContext context) {
        permissions.require(context.subject(), "OPERATION_REPROCESS");
        var reservation = idempotency.reserve(
                command.idempotencyKey(), command.requestHash(), context.transactionId());

        if (reservation.replay()) {
            return operations.requireReceipt(reservation.operationId());
        }

        Operation operation = Operation.accept(command, context);
        operations.insert(operation);
        outbox.append(operation.acceptedEvent());
        audit.recordAccepted(operation.auditEvent(command.reason()));
        idempotency.bind(command.idempotencyKey(), operation.id());
        return operation.receipt();
    }
}
```

## 6. Transaction

- 변경 Use Case Application Service가 Owner
- 업무 상태와 Outbox는 같은 DataSource·Transaction
- 외부 HTTP·Kafka ACK 대기를 Transaction 안에서 수행하지 않음
- `REQUIRES_NEW`는 독립 Commit 의미가 명확할 때만
- Self Invocation으로 Proxy 우회 금지
- 긴 Lock·File·Process는 Transaction 밖
- Optimistic Lock 충돌은 409
- Deadlock Retry는 제한·Jitter·Idempotency가 있을 때만

### 6.1 결과 불명

```text
DB Commit 성공
→ HTTP 응답 전 연결 단절
→ 호출자는 UNKNOWN_RESULT
→ 같은 idempotencyKey로 Status/Reconcile
→ 기존 operationId 반환
```

새 idempotencyKey로 재요청하면 중복 Side Effect가 발생할 수 있다.
