## 1. 배치 성공의 정의

Spring Batch `COMPLETED`는 기술 Metadata 상태다. 업무 성공은 **Job Metadata + 업무 Row/건수/금액/Hash + 외부 Attempt + Audit**가 대사 기준과 일치할 때 확정한다.

## 2. 핵심 상태와 용어

| 용어 | 의미 | 운영 판정 |
|---|---|---|
| Job | 업무 실행 정의 | name/version |
| JobInstance | 식별 Parameter가 같은 논리 실행 | businessDate 등 |
| JobExecution | 한 번의 실제 실행 | status/start/end/exit |
| StepExecution | Step 실행 상태 | read/write/skip/commit |
| ExecutionContext | Restart용 작은 상태 | cursor/checkpoint |
| Restart | 같은 Instance 이어 실행 | 동일 식별 Parameter |
| Reprocess | 새 의도/대상으로 다시 처리 | 새 Operation/Reason |
| Reconcile | 기술·업무 결과 비교 | 건수/금액/hash/target |

## 3. 유형 선택

| 유형 | 선택할 때 | Checkpoint | 대표 실패 |
|---|---|---|---|
| Tasklet | 파일 이동·Marker·단일 작업 | 완료 Marker | 부작용 뒤 Marker 저장 전 종료 |
| Chunk | 대량 Row 반복 | 마지막 Commit | 중복 Writer·Cursor Drift |
| File Job | Upload/Validate/Apply | File/Row 상태 | 일부 Row 반영 |
| Partition | 독립 범위 병렬 | Partition별 Execution | 중복 Claim·stale writer |
| Remote Worker | Manager/Worker 분리 | Partition/Message Attempt | Worker loss·ACK 유실 |
| Center-Cut | 기준시점 대상 Snapshot | Execution/Item Result | Preview Drift·Partial |

## 4. JobParameter 설계

식별 Parameter는 업무 의미가 있어야 한다. 단순 실행 시각을 식별값으로 사용하지 않는다.

권장 항목:

- businessDate / settlementDate.
- institutionCode / tenant / region.
- runType.
- selectionVersion 또는 snapshotHash.
- requestId/operationId.
- requestedBy/reason.

어떤 값이 JobInstance 식별에 포함되는지, 어떤 값이 운영 Metadata인지 구분한다.

## 5. Tasklet

Tasklet은 한 번의 명시적 부작용을 처리한다.

필수 계약:

- 입력/출력 Artifact.
- 시작 전 상태.
- 완료 Marker.
- 중복 실행 시 행동.
- 실패 중간 상태.
- Restart 시 확인할 Evidence.

파일 rename처럼 외부 부작용과 Metadata Commit이 분리되면 Marker/Checksum/대상 존재 여부로 재진입 시 중복 부작용을 차단한다.

## 6. Chunk

### 6.1 Reader

- 안정된 Sort Key.
- Restart Cursor.
- 실행 중 신규/변경 Row 유입 정책.
- Page/Fetch Size.
- Snapshot 또는 기준시각.

### 6.2 Processor

검증과 계산을 수행하고 외부 부작용은 만들지 않는다. `null` Filter와 오류를 분리하고 제외 이유를 집계한다.

### 6.3 Writer

- 업무 Key 기준 멱등 저장.
- 같은 Key·같은 Payload/다른 Payload 정책.
- Version/CAS.
- Chunk Transaction 안에서만 원자성 가정.
- 외부 전송은 Outbox/다음 Step으로 분리.

### 6.4 Commit Interval

Chunk Size는 성능 숫자가 아니라 **복구 단위**다. 처리시간, Lock, Memory, 재실행 비용, 외부 I/O를 함께 고려한다.

## 7. Retry·Skip·Rollback

| 오류 | Retry | Skip | Job 실패 | 비고 |
|---|---:|---:|---:|---|
| 일시 DB Deadlock | O | X | 한도 초과 | Transaction 재시도 |
| 입력 Validation | X | 정책 허용 시 | 한도 초과 | Row 오류 원장 필수 |
| Version Conflict | X | X | O | Snapshot Drift 의심 |
| 외부 Write Timeout | Blind Retry 금지 | X | UNKNOWN_RESULT | Target 대사 |
| Disk Full | X | X | O | 환경 복구 후 Restart |
| Poison Message | X | 격리 | 정책 | DLQ/Quarantine |

## 8. Stop·Restart·Abandon

### Stop

- 새 Chunk/Partition Claim 중지.
- 실행 중 Transaction의 안전 지점까지 처리.
- Stop 요청자·Reason·시각 기록.

### Restart

1. 같은 JobInstance인지 확인.
2. 마지막 Completed Step과 실패 Step 확인.
3. ExecutionContext/Checkpoint 검증.
4. 업무 Row와 Commit Count 대사.
5. 외부 Attempt 미종결 확인.
6. Restart 수행.
7. 완료 후 전체 합계 대사.

### Abandon

더 이상 Restart하지 않을 Execution을 명시적으로 폐기한다. 대체 Execution, Reason, 승인, 업무 미처리 범위를 남긴다.

## 9. Partition

Partition 계약:

- Partition Key와 범위.
- 서로 겹치지 않는지 검증.
- Claim Owner·Lease Expiry.
- Fencing Token.
- Partition별 Retry/Restart.
- 전체 합계와 누락/중복 검증.

stale worker가 Lease 만료 후 늦게 Write하지 못하도록 Fencing을 적용한다.

## 10. Remote Worker

Manager는 Partition 정의와 진행을 소유하고 Worker는 할당된 범위를 처리한다.

필수 상태:

`READY -> CLAIMED -> RUNNING -> SUCCEEDED | FAILED | UNKNOWN`

실패:

- Worker가 Claim 뒤 종료.
- 처리 Commit 뒤 결과 ACK 유실.
- Manager 재기동.
- 같은 Partition 중복 Delivery.

복구는 Lease·Fencing·Partition Result·업무 합계로 수행한다.

## 11. Job 등록·Version

Job Definition은 이름만 등록하지 않는다.

- Job Name/Version.
- Parameter Schema.
- Artifact/Job Pack Version.
- Required Capability.
- Permission/Approval Policy.
- Retry/Restart/Reprocess 정책.
- 예상 건수/시간/Resource.
- Reconcile Query/Rule.

Breaking Parameter/Checkpoint 변경은 새 Version으로 구분한다.

## 12. Scheduler

Scheduler 등록 항목:

- Schedule/Cron/Timezone.
- Calendar/Holiday.
- Misfire 정책.
- Concurrent 실행 허용 여부.
- Catch-up 한도.
- Deadline/SLA.
- Job Parameter Resolver.
- 실패 알림·Escalation.

Misfire는 무조건 바로 실행하지 않는다. 업무 날짜 중복과 하류 영향, Cut-off를 판단한다.

## 13. Center-Cut

### 13.1 정의

기준시점에서 대상 Snapshot을 만들고 승인된 대상을 Partition/Chunk로 처리한 뒤 Item Result와 전체 합계를 대사하는 일괄 처리 패턴이다.

### 13.2 흐름

1. 조건 입력.
2. Dry Run/건수 Preview.
3. 대상 Snapshot + hash/version 생성.
4. 승인.
5. Execution 생성.
6. Partition/Chunk 처리.
7. Item Result 기록.
8. Partial/Unknown 분류.
9. Reprocess 대상 생성.
10. 업무 합계 Reconcile.
11. 종결 Audit.

### 13.3 Preview Drift

승인 시 Snapshot Hash와 실행 직전 Hash가 다르면 실행을 중단하거나 정책상 재승인을 요구한다.

## 14. Artifact·Job Pack

Job Pack에는 최소:

- Job 정의/Version.
- 실행 Artifact SHA.
- Parameter Schema.
- Migration/SQL Version.
- Config Snapshot.
- Dependency/Starter Lock.
- Test Result.
- Rollback/LKG.

Runner/Worker/Agent가 서로 다른 Pack을 실행하지 않도록 Checksum을 확인한다.

## 15. Runner·Worker·Agent

| 구성 | 책임 | 금지 |
|---|---|---|
| Runner | Execution 시작·Job JVM | Scheduler 정책 소유 |
| Worker | Partition 처리 | 전체 Job 성공 추정 |
| Agent | 허용 Process Start/Stop/Status | 임의 명령 실행 |
| Control Server | 상태/조치/승인 | 업무 DB 직접 수정 |

## 16. Lease·Claim·Fencing

- Lease는 소유 기간.
- Claim은 작업 소유 의사.
- Fencing Token은 오래된 소유자의 Write 차단.
- Heartbeat 누락만으로 바로 실패 확정하지 않고 Grace/Clock Skew를 고려한다.

## 17. UNKNOWN_RESULT

외부기관, Worker ACK, Agent 명령, Scheduler Dispatch 등에서 결과를 모르면:

1. 같은 요청을 반복하지 않는다.
2. Execution/Attempt/Target ID를 조회한다.
3. Spring Batch Metadata와 업무 원장을 비교한다.
4. Target이 부작용을 수행했는지 확인한다.
5. 성공/실패/보상/재처리 중 하나로 종결한다.

## 18. ADM 운영

ADM에서는 최소 다음을 볼 수 있어야 한다.

- Job Definition/Version.
- Schedule/Misfire.
- Execution/Step/Partition.
- Read/Write/Skip/Commit Count.
- Checkpoint/Last Heartbeat.
- Lease/Fencing.
- Worker/Agent 상태.
- Stop/Restart/Abandon/Reprocess.
- UNKNOWN/PARTIAL/Reconcile.
- Audit/Approval.

## 19. Process Kill과 Restart 통합 실습

1. 10,000건 입력을 준비한다.
2. Chunk Size를 정하고 Job을 실행한다.
3. 중간 Commit 이후 Process를 강제 종료한다.
4. Metadata의 마지막 Commit/ExecutionContext를 확인한다.
5. 업무 Row 중복/누락을 확인한다.
6. 같은 Instance로 Restart한다.
7. 완료 후 입력 건수·금액 = 결과 + 제외 + 실패를 대사한다.

정상 판정: Kill 이후 이미 Commit된 Row가 중복되지 않고 미처리 Row부터 이어지며 최종 업무 합계가 일치한다.

## 20. Worker Loss/Fencing 통합 실습

1. Partition을 여러 Worker에 분배한다.
2. Worker 하나의 Heartbeat를 중단한다.
3. Lease 만료 뒤 새 Worker가 Claim한다.
4. 이전 Worker를 늦게 복귀시킨다.
5. stale Fencing Token Write가 거절되는지 확인한다.
6. Partition Result를 대사한다.

## 23. Step Executor 유형

Spring Batch Step 안에서 다음 실행 방식을 선택할 수 있다.

- Java Tasklet/Chunk.
- 승인된 Shell/Process.
- File Watch/Move/Transfer.
- Service/API 호출.
- Message/Event 처리.

Shell/Process는 Allowlist, Artifact Trust, Working Directory, Environment, Timeout, Process Tree, stdout/stderr Size Budget, Secret Redaction을 적용한다.

## 24. Resource Bound와 Backpressure

- Reader Fetch/Page Size.
- Chunk Size.
- Partition 수.
- Worker Concurrency.
- Queue Capacity.
- stdout/stderr 최대 크기.
- File/Message Payload 상한.
- Global/Domain/Target TPS·RPS.

Rate 제한을 변경할 때 진행 중 Execution과 SLA 영향을 Preview하고 pause/drain을 지원한다.

## 25. Remote Partition/Chunk Transport

Remote topology는 stable correlation ID와 Durable Transport를 사용한다. 제품 Profile에서 in-memory channel로 조용히 대체하지 않는다.

확인:

- Manager restart.
- Worker restart.
- Duplicate delivery.
- Late reply.
- Broker outage/rebalance.
- Reply response loss.

## 26. Scheduler Claim과 Job Start 사이 복구

Trigger를 Claim했지만 Job Start 응답을 잃는 경우를 별도 상태로 둔다.

1. triggerAttemptId 저장.
2. JobInstance/Execution 존재 여부 조회.
3. 존재하면 기존 실행 연결.
4. 존재하지 않으면 Claim/Lease 상태 확인 뒤 재기동.
5. 중복 JobInstance를 만들지 않는다.

## 27. Center-Cut Rate·Pause·Drain

Center-Cut은 global/domain/target rate와 concurrency를 관리한다. Pause는 신규 Claim을 막고 Drain은 실행 중 Item을 안전 지점까지 처리한다. Resume 시 이전 Fencing/Checkpoint를 확인한다.

## 29. EDU-BAT 실행/전환 규칙

배치 예제의 완료 판정은 Spring Batch 상태만 보지 않는다. `JobInstance/JobExecution/StepExecution`과 CPF 승인·Operation·Attempt·Lease/Fencing·업무 합계/대사 결과를 연결한다.

1. JobParameter가 JobInstance Identity를 만드는지 확인한다.
2. Chunk/Tasklet/Partition/Remote Worker의 Commit 경계를 문서화한다.
3. Process Kill을 Commit 전/후로 나누어 재현한다.
4. Stop/Restart/Abandon/Reprocess를 같은 의미로 섞지 않는다.
5. UNKNOWN_RESULT는 대상별 대사 전 무조건 재처리하지 않는다.
6. 실패건 재처리는 원 실행과 새 Attempt를 연결하고 prior result를 보존한다.
7. Center-Cut은 Preview Snapshot/Hash와 실제 대상 Drift를 검사한다.
8. Agent/Worker는 lease loss 뒤 stale write를 fencing으로 차단한다.
