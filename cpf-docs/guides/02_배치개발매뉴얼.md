## 문서 사용 계약

| 상태 | 의미 |
|---|---|
| `완료` | 최신 exact SHA에서 Source·Consumer·Failure/Recovery·필수 Runtime Evidence가 모두 확인됨 |
| `부분 구현` | 일부 계층만 연결되었거나 Legacy/대체 경로가 Primary로 남음 |
| `미구현` | 제품 Source 또는 필수 수직 연결이 없음 |
| `미검증` | Source는 있으나 필요한 실제 환경 검증이 실행되지 않음 |
| `실패` | 필수 Gate·Scenario가 실패함 |
| `재확인 필요` | Source·Evidence·SHA·환경이 상충하거나 불명확함 |

- **Source-confirmed**: 기준 SHA의 Source·Config·SQL·Route·Script에서 직접 확인했다.
- **Product contract**: CPF 정본이 요구하는 동작이다. 실제 Runtime Evidence가 없으면 `미검증`으로 표시한다.
- **Operator procedure**: 운영자가 수행해야 하는 절차다. 화면·권한·환경 차이는 실제 배포 Catalog를 우선한다.
- **Prohibited**: 성공처럼 보여도 제품 안정성·감사·복구를 깨뜨려 금지하는 방식이다.

```text
Requirement → Owner → Public API/SPI → Application/Policy → Adapter/State
→ Runtime Consumer → Security/Approval/Audit → Failure/Recovery
→ Test/Evidence → Guide/EDU → Legacy 제거
```

## 3. Job·Step 설계

| 방식 | 적합 | 주의 |
|---|---|---|
| Tasklet | 단일 명령·File·API·Shell | Checkpoint와 Side Effect 대사 |
| Chunk | 대량 Record 처리 | Reader·Processor·Writer 재시작 |
| Flow | 조건 분기·다단계 | ExitStatus·실패 전파 |
| Parallel Flow | 독립 Step 병렬 | 공유 자원·총량 |
| Partition | 범위 분할 | 중복·누락 없는 Range |
| Remote | 별도 Worker | Message 중복·Timeout·Fencing |

### 3.1 Step Handler 계약

`BatchStepHandler` 구현은 다음을 제공한다.

- 지원 Step Type
- 입력 Parameter Schema
- Resource Policy
- Retry 가능 오류
- Stop·Cancellation 확인
- Idempotency·Checkpoint
- 결과·Metric·Evidence
- Masking
- Recovery 방법

### 3.2 Tasklet 예

```java
public final class ReconcileTasklet implements Tasklet {
    private final ReconciliationService service;

    @Override
    public RepeatStatus execute(StepContribution contribution, ChunkContext context) {
        var executionContext = context.getStepContext()
                .getStepExecution().getExecutionContext();
        String cursor = executionContext.getString("cursor", "");
        ReconcilePage page = service.reconcile(cursor);

        executionContext.putString("cursor", page.nextCursor());
        contribution.incrementReadCount(page.readCount());
        contribution.incrementWriteCount(page.resolvedCount());

        return page.finished() ? RepeatStatus.FINISHED : RepeatStatus.CONTINUABLE;
    }
}
```

Side Effect가 있다면 Cursor 저장 시점과 Transaction을 명확히 한다.

### 3.3 Chunk

- Reader는 재시작 가능한 Cursor를 제공한다.
- Processor는 가능한 한 Pure Function으로 만든다.
- Writer는 Batch Size·DB 제한·외부 Rate를 고려한다.
- Skip·Retry는 업무 의미와 Audit를 가진다.
- Commit Interval은 성능뿐 아니라 실패 후 재처리량으로 결정한다.

### 3.4 Flow·조건 분기

- ExitStatus와 BatchStatus를 혼용하지 않는다.
- 조건식은 Definition Version에 포함한다.
- 실패 Step 이후 Cleanup이 원 실패를 숨기지 않는다.
- 병렬 Flow는 공유 File·Table·External Quota를 합산한다.

## 5. 실제 실행 API

Source: `CenterCutControlController`, Base `/internal/v1/center-cut`.

### 5.1 Start

```http
POST /internal/v1/center-cut/executions
Content-Type: application/json

{
  "approvalId": "APR-20260731-0004",
  "reason": "INC-2041 대사 재처리",
  "idempotencyKey": "cc-20260731-0004",
  "fencingToken": 192,
  "parameters": {
    "businessDate": "2026-07-31",
    "partitionCount": 8
  }
}
```

- 인증 Principal 필수
- `approvalId`, `reason`, `idempotencyKey` 필수
- `fencingToken` 양수
- `202 Accepted`
- 승인 Resolver→Control Port→`JobOperator`

### 5.2 Stop

```http
POST /internal/v1/center-cut/executions/{jobExecutionId}/stop
Content-Type: application/json

{"reason":"INC-2041 입력 오류 확인"}
```

`accepted=true`는 접수다. `JobExecution.status=STOPPED`와 Worker 중단을 별도 확인한다.

### 5.3 Restart

```http
POST /internal/v1/center-cut/executions/{jobExecutionId}/restart
Content-Type: application/json

{"reason":"INC-2041 입력 수정 후 재시작","fencingToken":193}
```

- 같은 JobInstance·ExecutionContext
- 현재 Fencing Token
- 완료 Step 재실행 정책
- Artifact·Definition·File Checksum

### 5.4 Abandon

```http
POST /internal/v1/center-cut/executions/{jobExecutionId}/abandon
Content-Type: application/json

{"reason":"INC-2041 수동 대체 처리 확정"}
```

Abandon은 재시작 불가 상태로 만들 수 있어 대체 재처리·감사·승인 근거가 필요하다.

### 5.5 Reconcile

```http
POST /internal/v1/center-cut/executions/{cpfExecutionId}/reconcile
```

Ledger의 최신 Link와 실제 `JobRepository` 상태를 다시 읽어 결과를 갱신한다.

- Permission
- Reason·Ticket
- Approval
- Expected Version
- Fencing Token
- Actor
- Audit
- 결과·Error·Reconcile Link
