## 6. Secret·Certificate

- Secret은 File/External Provider Reference로 전달한다.
- File은 symlink가 아닌 Regular File, 최소 Permission, Size 상한을 사용한다.
- Environment Variable은 Process 조회·Dump 노출 위험을 평가한다.
- Certificate는 Key ID, SAN, Expiry, Trust Chain, Revocation, Rotation, Rollback을 관리한다.
- Log·Audit·Evidence·Command Line에 원문을 남기지 않는다.

BZA Secret 파일 삭제 실패는 Bootstrap 실패로 처리된다. 저장장치 잔존 위험은 OS Secret Store와 운영 절차로 보완한다.

## 17. 장애 Runbook

### Build Settings 실패

증상: Settings evaluation 또는 Plugin resolution에서 Canonical Plugin ID·Marker·Included Build 공급 계약 불일치.
확인: `settings.gradle`, 두 `cpf-tools/build/*` 경로.
조치: 승인된 설계에 따라 Source 복원 또는 includeBuild 제거.
정상 판정: `gradlew projects`, version gate, test, build Exit 0.

### DB 장애

Pool·Network·Credential·Schema·Lock·Disk를 분리한다. Side Effect 가능성이 있으면 Unknown 원장을 조회한다. 복구 후 Transaction·Outbox·Batch·Session 대사.

### Kafka 장애

Broker·ACL·TLS·Topic·Lag·Rebalance·Producer ACK를 확인. Blind Replay 전 Inbox/Idempotency와 Side Effect 확인.

### Instance 장애

Health·Lease·Draining·In-flight·Version·Config 확인. Stale writer 차단 후 takeover. 종료되지 않은 Process Tree와 File Lock 확인.

### Disk·Memory

Disk full 시 Temp·Log·Archive·DB 영향 분리. 승인된 Retention 대상만 삭제. OOM 후 in-flight·Batch·Outbox·Unknown 대사.

### Network·TLS

DNS·Route·Firewall·SNI·Certificate Chain·Clock·Proxy Header 확인. Connect 전 실패와 요청 전송 후 Response loss를 구분.

### Security Incident

Credential revoke·Key rotate·Session invalidate·Access scope 차단. Evidence를 보존하되 Secret 원문을 복제하지 않는다.

## 부록 E. 배포 방식별 판정

### Rolling

- Mixed Version API·DB·Message Compatibility가 선행된다.
- 한 Instance씩 Drain→교체→Readiness→Traffic 복귀한다.
- 진행 Transaction·Batch·Session 인계 여부를 확인한다.

### Blue-Green

- Green에 동일 DB를 사용할 때 Schema Compatibility를 먼저 확인한다.
- Smoke와 데이터 대사 후 Traffic을 전환한다.
- 전환 후 Side Effect가 발생하면 단순 Traffic 원복만으로 Rollback이 끝나지 않는다.

### Canary

- 대상 Traffic·기간·중단 Threshold를 명시한다.
- Error·Latency뿐 아니라 업무 상태·Unknown·Audit를 비교한다.
- 실패 시 Canary Instance만 제외하고 Config·DB 변경 영향은 별도로 복구한다.

## 부록 G. 환경변수와 Partial Apply 확인

환경변수는 배포 Manifest에 Key·Scope·Secret 여부·변경자·승인·적용 Version을 기록한다. Spring Property의 환경변수 이름은 배포 도구의 relaxed binding 결과를 실제 기동 로그와 Actuator Sanitized Config에서 확인한다.

Config 또는 Route가 일부 Instance에만 적용된 `Partial Apply` 상태에서는 전체 적용으로 판정하지 않는다. Instance별 desiredVersion·actualVersion·checksum·ACK/NACK·error를 비교하고, 미적용 Instance를 Traffic에서 제외한 뒤 재적용 또는 Rollback한다.

## 부록 H. Property 확인 명령과 정상 결과 기록

Property별 확인 명령은 Secret을 출력하지 않는 방식으로 작성한다. 예시는 `gradlew properties`, Sanitized Actuator Config, Process Environment Key 존재 여부, 기동 로그의 Effective Profile·Version·Checksum 확인이다. 정상 결과에는 Key 원문 값이 아니라 적용 Source, Scope, Masked 값, Consumer, Restart 여부, desiredVersion·actualVersion 일치 여부를 기록한다. 오류 시 이전 승인 Version으로 Rollback하고 Instance별 적용 상태를 다시 조회한다.

Property 변경은 Agent 재기동이 필요하다고 가정하고, 실제 Refresh Bean이 확인된 경우에만 재기동 없는 적용으로 분류한다. QA34에서 DNS 검증과 실제 HTTP Connection Address가 고정되지 않는 경계가 `재확인 필요`다. Rebinding·Redirect·Proxy·혼합 A/AAAA Test 전에는 신뢰되지 않은 Repository를 등록하지 않는다.

### 23.10 Observability·Resilience·Feature Flag·Secret

| 기능 | CPF Custom Key | 실제 설정 Owner | 확인 방법 |
|---|---|---|---|
| Observability | 없음 | Spring Boot Actuator·Micrometer Exporter와 배포 Profile | `ObservationRegistry` Bean, Trace/Metric Export, Endpoint 노출·권한 |
| Resilience | 없음 | Spring Cloud CircuitBreaker/Resilience4j Instance Config | Route/Service별 Timeout·Retry·Circuit State와 Fault Test |
| Feature Flag | 없음 | 등록된 OpenFeature Provider | Provider Ready, Flag Evaluation Context, Default/Error 결과 |
| Secret | 일반 Secret Value Key 없음 | 고객이 구현·등록한 `CpfSecretProvider` | Provider Bean 수, Metadata, Rotation, Consumer Reload; 0개면 기동 실패 |

이 네 기능은 CPF Prefix가 없다고 설정이 불필요한 것이 아니다. 운영자는 각 OSS/Spring 설정 Key를 실행 Module의 Profile과 Deployment Manifest에서 추출하고 다음을 기록한다.

- Key·환경변수·Type·Default·필수·범위.
- Provider/Exporter/Instance Name과 실제 Consumer.
- Secret 여부·Masking·Reload 또는 재기동.
- 오류 시 Fail-open/Fail-closed 여부.
- 확인 명령·정상 결과·Fault Test·Rollback Version.

### 23.11 Spring Boot 표준 운영 Property

CPF Application별 최소 Inventory는 다음 Prefix를 포함한다. 실제 Key는 해당 Module의 `application*.yml|properties`, Config Server/Secret Manifest, Deployment Descriptor에서 추출한다.

| Prefix | 운영 책임 | 필수 확인 |
|---|---|---|
| `server.*` | Port·Context·Compression·Shutdown·TLS | Listener, Graceful Shutdown, Connector Limit |
| `spring.datasource.*` | URL·Driver·Pool·Timeout·Validation | Vendor·계정·Pool·Credential Reference·Health |
| `spring.flyway.*` | Location·Schema·Baseline·Validate | Migration Version·Checksum·Repair 금지 기준 |
| `spring.kafka.*` | Broker·Security·Producer·Consumer | TLS/SASL·ACK·Idempotence·Group·Offset·Poll |
| `spring.batch.*` | Job Auto Start·Metadata Schema | `job.enabled=false`, Schema 초기화 정책, JobRepository |
| `spring.session.*` | JDBC Table·Cleanup | V83/V86, Session TTL, Cleanup Scheduler |
| `management.*` | Health·Metric·Endpoint | 노출 Endpoint·인증·Sanitization |
| `logging.*` | Level·File·Rotation | PII/Secret Masking·Retention·Disk |

문서에 정적 예시 값을 복사해 운영 정본으로 삼지 않는다. 배포하려는 exact SHA와 Profile의 Effective Config를 Sanitized 형태로 추출하고, 이 매뉴얼의 Property 열 형식으로 승인한다.

## 24. Secret·Certificate

- Secret Value를 YAML, Git, Process Argument, Screenshot, Audit Message에 남기지 않는다.
- File Secret은 ACL, No Symlink, Size, Read 후 Memory Clear, 삭제 결과를 확인한다.
- Secret Rotation은 Provider Metadata, Consumer Reload, Dual-Key Window, Rollback Version을 확인한다.
- TLS Certificate는 Subject/SAN, Chain, Key Usage, Expiry, Trust Store, Reload/재기동, Rollback을 기록한다.
- Gateway Certificate ≤30일 KPI와 실제 Certificate Inventory를 대조한다.

## 25. 3DB 설치·Migration·Rollback·Drift

### Artifact 경로

- Canonical: `cpf-tools/db/canonical/platform-schema.json`.
- Vendor Migration: `cpf-tools/db/vendor/{mariadb|postgresql|oracle}/migration/...`.
- Rollback: Vendor별 `rollback`, Destructive는 별도 승인.
- Runtime Query: `runtime/<module>/repository`.
- Checksum: 각 Vendor `checksums.sha256`.

### 현재 신규 Version

- V86 BFF Encrypted Credential Vault.
- V87 Batch Remote Message Ledger.
- V88 Scheduler Durable Launch Outbox.
- V89 Batch Execution Idempotency Lifecycle.
- V90 Deployment Request Hash/Reconciliation.
- V91 BZA Bootstrap Claim Recovery.

### 실행 절차

1. Backup과 Restore Point를 만든다.
2. Runtime Write를 Drain/정지한다.
3. Vendor·Schema·Current Version·Checksum을 확인한다.
4. Migration을 Dry/Info 후 적용한다.
5. Table·Column·PK/UK/FK/Check/Index·Backfill을 실제 SQL로 검증한다.
6. Application Query·Claim·Update를 실행한다.
7. Rollback 또는 Forward Recovery를 Test한다.
8. Canonical Manifest와 Drift를 비교한다.

Token/String 기반 Semantic Script는 실제 SQL 실행을 대신하지 않는다.

## 26. Kafka 설치·운영

- Broker/Topic/Partition/Replication/Min ISR/Retention/ACL/TLS/SASL을 기록한다.
- Producer Idempotence·ACK·Delivery Timeout과 Consumer Group·Offset·Max Poll·DLT를 확인한다.
- Batch Remote Request/Reply Topic과 일반 업무 Topic을 분리한다.
- Lag·Under-replicated Partition·Disk·Controller 상태를 Metric으로 감시한다.
- Broker 장애·ACK 유실·Consumer Kill·Late Reply·DLT Replay를 Test한다.

## 27. 신규 설치 절차

```text
Baseline SHA·Artifact Hash 확인
→ OS Account·Directory·ACL
→ Java/Node/PowerShell
→ Artifact Mode와 Repository
→ Secret·Certificate
→ DB 신규 설치·Migration
→ Kafka Topic·ACL
→ Config/Profile
→ ADM/BZA/Gateway/Batch 선택 Module 기동
→ Health/Readiness/Probe
→ ADM Menu·Permission·Bootstrap
→ 정상/오류/Fault Smoke
→ Backup·Rollback Point
→ Evidence·인계
```

현재 Build Gate가 실패하므로 Source Build 설치는 중단 상태다. 승인된 동일 SHA Artifact가 별도로 존재하면 Manifest·SBOM·Signature·DB Pack 일치 여부를 먼저 검증한다.

## 28. 기동·종료·Health

- 기동 순서: DB/Kafka/Secret Provider → Owner Runtime → Batch Control/Worker → Gateway → ADM/BZA Frontend.
- Readiness는 Process 존재가 아니라 DB/Kafka/Owner Port/Snapshot/Spool/Required Permission까지 확인한다.
- 종료 전 Traffic Drain, Scheduler Dispatch 중지, Worker Claim 중지, Outbox Flush, Log Flush를 확인한다.
- 강제 종료 뒤 Unknown/Reconciliation 대상과 Lock/Lease 만료를 점검한다.

Local Script는 `start-cpf-local.ps1`, `status-cpf-local.ps1`, `stop-cpf-local.ps1`의 `Get-Help`와 실제 Parameter를 기준으로 사용한다.

## 29. 배포

### Rolling

Instance Drain→Artifact/Config 변경→Migration 호환 확인→Start→Readiness→Canary Traffic→Resume를 한 Instance씩 수행한다. DB Breaking Change를 같은 단계에서 적용하지 않는다.

### Blue-Green

Green 전체 설치·Migration 호환·Probe·Gateway Binding 준비→Approval→Traffic Switch→Observe→Blue 유지/제거. Session·Cache·File·Message Consumer 중복을 확인한다.

### Canary

대상 Instance/Member Canary Percent, Success/Error/P95/P99, Unknown, Business KPI를 확인한다. 기준을 넘으면 신규 Traffic을 차단하고 LKG로 Rollback한다.

### Partial Apply

Target별 Desired/Actual Version, ACK/NACK, Error, Health를 기록한다. 일부 성공을 전체 성공으로 처리하지 않는다. Reconcile 뒤 동일 상태로 맞추거나 전체 Rollback한다.

## 30. Log·Metric·Trace·Capacity

### Log

Transaction/Operation/Execution/Attempt/Instance ID, Status, Failure Stage를 남기며 PII/Secret을 Masking한다. Spool Backlog·Disk·Retention을 감시한다.

### Metric

- JVM CPU/Heap/GC/Thread.
- HTTP TPS/Error/Latency Percentile.
- DB Pool/Slow Query/Lock/Replication.
- Kafka Lag/ISR/Disk.
- Batch Running/Queue/Chunk/Retry/Unknown.
- Gateway Circuit/Retry/Spool/Cert/Drift.
- Agent Process/Artifact/Health.

### Capacity

Load Model, Peak TPS, Batch Window, File Size, Retention, Worker/Partition 수를 기록하고 70/80/90% 단계별 경보·증설 행동을 정의한다.

## 31. Backup·Restore

- DB Full/Incremental/WAL/Archive와 Encryption/Retention.
- Kafka는 업무 원장·Replay 정책과 Topic Retention을 함께 본다.
- Config/Secret Metadata/Certificate/Artifact Manifest/DB Pack을 Backup한다.
- Log/Spool은 감사 요구와 재생 가능성을 구분한다.
- Restore는 격리 환경에서 exact Schema/Checksum, Application Read/Write, Reconciliation을 실행한다.
- RPO/RTO를 실제 Restore 시간으로 측정한다.

## 32. Upgrade·Rollback

1. Source/Artifact/DB/Frontend/SBOM exact SHA를 고정한다.
2. 호환 범위와 Deprecated API를 확인한다.
3. DB Expand→Application→Contract→DB Contract 순서를 사용한다.
4. Canary와 Fault Test를 수행한다.
5. Rollback 가능 시점과 DB Forward Recovery 시점을 구분한다.
6. Rollback 뒤 Version·Health·Data·Message·Audit를 확인한다.

## 33. DR

DR 문서에는 Primary/Standby Topology, DNS/Gateway Switch, DB Replication, Kafka, Secret/Certificate, Artifact, Backup, Fencing, Split-brain 방지, 복귀 절차를 포함한다. DR 전환 중 양쪽 Scheduler/Worker/Gateway가 동시에 Owner가 되지 않도록 Lease/Fencing을 확인한다.

## 34. 장애 Runbook

### Build/Artifact

증상: Plugin Resolution/Marker/Coordinate 실패. 조치: Mode·Repo·Credential·Included Build·Plugin ID·Marker를 확인하고 empty-cache `help`부터 재실행. Local Repo로 우회하지 않는다.

### DB

Connection/Pool/Migration/Lock/Disk/Replication을 분리한다. Write 중지, Backup, Vendor Status, Blocking Session, Migration Version, Checksum, Drift를 확인한다. 직접 상태 Row 수정 금지.

### Kafka

Broker/Topic/ACL/Producer ACK/Consumer Lag/DLT를 확인한다. Message Replay 전 Side Effect와 Inbox를 대사한다.

### Instance

Load Balancer/Gateway에서 Drain, In-flight/Lease/Lock 확인, Thread Dump/Heap/Disk/Log 확보, 재기동, Readiness, Reconcile, Resume 순서다.

### Disk/Memory

Spool·Log·Temp·Heap Dump·Artifact Cache를 정확히 식별한다. Source/DB/Secret을 삭제하지 않는다. Retention 변경과 Capacity 증설을 함께 수행한다.

### Network/TLS

DNS, Route, Firewall, Proxy, Certificate Chain/SAN/Expiry, TLS Version, Host/IP Identity를 확인한다. DNS 검증 후 실제 연결 Address가 달라질 수 있는 Gateway/Agent는 Rebinding Risk로 격리한다.

### Security

Credential 폐기·Rotation, Session Revoke, IP Allowlist, Break-glass 종료, Audit 보전, 영향 API 401/403 검증을 수행한다.
