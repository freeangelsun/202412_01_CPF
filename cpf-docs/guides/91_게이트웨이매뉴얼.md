## 1. 선택 기준

Gateway는 공통 진입 정책, Route Control Plane, Upstream Failover, 중앙 거래 Ledger가 필요한 환경에서 선택한다.

비선택:

- Channel이 Domain에 직접 진입
- 각 Service Ingress가 정책 소유
- `cpf-gateway`가 필수 Dependency·기동 조건이 되지 않음

Gateway를 선택해도 Domain 인증·권한·업무 Validation을 대체하지 않는다.

## 2. 현재 Architecture

| Source | 책임 |
|---|---|
| `CpfScgPrimaryRouteConfiguration` | Business Request Router |
| `CpfScgPrimaryHandler` | Route·Authn/Authz·Retry·Circuit·Ledger |
| `CpfScgTargetResolver` | Registry UP Target |
| `CpfGatewayLedgerCompletionFilter` | Response 종료 시 Transaction 완료 |
| `CpfGatewayRouteSnapshot` | 현재 Route Snapshot |
| `CpfGatewayPathRewriter` | Path Rewrite |

SCG MVC Router는 `/**`를 처리하되 제외:

- `/actuator/**`
- `/internal/**`
- `/api/gateway/control/**`

```text
Client
→ SCG MVC Router
→ Route Snapshot
→ Authentication
→ Authorization
→ Reason Policy
→ Ledger begin
→ Target Resolver
→ Circuit Breaker
→ Idempotent Retry
→ SCG HTTP Handler
→ Attempt Ledger
→ Completion Filter
→ complete / UNKNOWN_RESULT
```

## 6. 보안

## 7. Retry·Circuit·Attempt Ledger

### 7.1 Retry

현재 `CpfScgPrimaryHandler`:

- `route.idempotent()`일 때만
- 최대 `maxRetryCount + 1`
- 50ms Wait
- IOException·TimeoutException
- Attempt마다 Target·상태·오류 기록

Non-idempotent Route는 1 Attempt다.

### 7.2 Circuit

Circuit 이름 `gateway-<routeId>`. Open·Half-open·Close Metric과 Target Health를 함께 본다.

### 7.3 Attempt

- attemptId·number
- target instance·host·port·scheme
- 시작·종료·duration
- SUCCESS/FAILED
- Protocol Status
- failureCode·sanitized message
- unknown flag

### 7.4 Completion

| 조건 | 결과 |
|---|---|
| 정상 <400 | `SUCCESS` |
| 4xx | `REJECTED` |
| 5xx | `FAILED` |
| IOException/Servlet/Runtime failure | `UNKNOWN_RESULT` |

응답 쓰기 중 연결 단절은 Upstream Side Effect가 이미 발생했을 수 있다.

## 8. UNKNOWN_RESULT Reconciliation

1. Gateway transactionId
2. Attempt별 Target·시각·오류
3. Upstream operationId·Idempotency Key
4. Upstream DB/Status
