# CPF 용어와 계약 참조

[← 문서 홈](README.md) · [제품 소개](../../README.md) · [구조와 배포](CPF_ARCHITECTURE_AND_TOPOLOGY_GUIDE.md)

> **목적**: CPF 문서, 코드, API, 화면과 검증 증적에서 같은 의미로 사용해야 하는 용어와 상태를 정의한다.
> **표기 원칙**: 본문은 한글을 우선하고 클래스·메서드·설정 키·상태 코드·제품명은 원문 식별자를 유지한다.

---

## 1. 기본 표기

| 권장 표기 | 식별자·영문 | 의미 |
|---|---|---|
| 모듈 | 모듈 | 독립 소유권과 의존 경계를 가진 코드·배포 단위 |
| 실행 환경 | 실행 환경 | 애플리케이션이나 작업을 실제 실행하는 프로세스·환경 |
| 공개 API | 공개 API | 고객과 다른 모듈이 사용하는 안정 계약 |
| 확장 SPI | SPI | 고객 어댑터가 구현하는 확장 계약 |
| 내부 구현 | 내부 구현 | 제품 외부에서 직접 의존하면 안 되는 구현 |
| 업무영역 | 업무영역 | 독립 업무 기능, 공개 계약과 데이터 소유권을 가진 영역 |
| 시스템 코드 | SystemCode | 내부 식별에 사용하는 3자리 대문자 코드 |
| 거래 식별자 | `transactionId` | 하나의 사용자·업무 요청 전체를 연결하는 식별자 |
| 구간 식별자 | `segmentId` | 호출·이벤트·작업 단계의 식별자 |
| 작업 식별자 | `operationId` | 멱등 명령과 운영 조치를 구분하는 식별자 |
| 시간 제한 | 시간 제한 | 호출이나 작업이 기다릴 수 있는 최대 시간 |
| 재시도 | 재시도 | 안전 조건을 만족할 때 동일 의미의 요청을 다시 수행 |
| 회로 차단기 | Circuit Breaker | 연속 장애 대상의 호출을 일시 차단하는 보호 장치 |
| 결과 불명 | `UNKNOWN_RESULT` | 요청 처리 여부를 확정할 수 없는 상태 |
| 상태 대사 | 상태 대사 | 기대 상태와 실제 상태를 비교해 차이를 확정·복구하는 절차 |
| 보상 | 보상 | 이미 반영된 업무 효과를 반대 의미의 거래로 해소하는 절차 |
| 재생 | 재생 | 보존된 사건·메시지를 승인된 범위에서 다시 전달 |
| 재처리 | Reprocess | 원본 입력이나 실패 자료를 기준으로 업무 처리를 다시 수행 |
| 재시작 | Restart | 같은 실행 인스턴스를 체크포인트에서 이어서 수행 |
| 재실행 | Rerun | 새 실행 인스턴스를 만들어 처음 또는 지정 범위부터 수행 |
| 임대 | 임대 | 일정 시간 동안 작업 소유권을 부여하는 기록 |
| 점유 | 점유 | 처리할 대상을 특정 실행자가 가져가는 행위 |
| 세대 토큰 | 세대 토큰 | 오래된 소유자의 늦은 결과를 거부하기 위한 증가 번호 |
| 정본 불일치 | 정본 불일치 | 기대 구성·스키마·버전과 실제 상태가 다른 상황 |
| 확인 응답 | ACK | 설정·배포·메시지를 수신하고 적용한 결과 |
| 검증 증적 | 검증 증적 | 기준 Commit, 명령, 환경과 실제 결과를 입증하는 자료 |

## 2. 모듈 코드

| 코드 | 모듈 | 책임 |
|---|---|---|
| `CPF` | `cpf-core` | 기술 기반과 공개 계약 |
| `CMN` | `cpf-common` | 고객 업무 공통 |
| `ADM` | `cpf-admin` | 플랫폼 운영과 통제 |
| `BZA` | `cpf-biz-admin` | 업무 관리 |
| `GWY` | `cpf-gateway` | 선택형 외부 진입 |
| `BAT` | `cpf-batch` | 배치 실행 제품군 |
| `MBR` | `cpf-member` | 생성 기준 업무영역 |
| `REF` | `cpf-reference` | 교육·참조 구현 |

생성 업무영역은 읽을 수 있는 `DomainName`과 내부 식별용 3자리 `SystemCode`를 구분한다.

## 3. 오류 분류

| 공개 분류 | HTTP 예 | 의미 | 기본 재시도 |
|---|---:|---|---|
| `VALIDATION` | 400 | 형식·범위·계약 위반 | 금지 |
| `UNAUTHORIZED` | 401 | 인증 없음·만료 | 인증 갱신 후 판단 |
| `FORBIDDEN` | 403 | 권한 부족 | 금지 |
| `NOT_FOUND` | 404 | 대상 없음 | 금지 |
| `CONFLICT` | 409 | 버전·중복·상태 전이 충돌 | 최신 상태 확인 후 판단 |
| `RATE_LIMITED` | 429 | 호출량 제한 | 안내된 대기시간 이후 가능 |
| `TIMEOUT` | 504 | 제한 시간 초과 | 멱등성과 시간 예산 확인 |
| `TARGET_DOWN` | 503 | 대상 연결 불가 | 일시 장애일 때 가능 |
| `CIRCUIT_OPEN` | 503 | 장애 보호 차단 | 회복 대기 후 가능 |
| `UNKNOWN_RESULT` | 202/409 등 계약별 | 처리 여부 미확정 | 무조건 재시도 금지 |
| `INTERNAL` | 500 | 예상하지 못한 내부 오류 | 원인 분류 전 금지 |

전송 계층의 예외 이름을 공개 계약으로 그대로 노출하지 않는다.

## 4. 인스턴스 상태

| 상태 | 의미 | 신규 요청 |
|---|---|---|
| `UP` | 정상 처리 가능 | 허용 |
| `DEGRADED` | 일부 기능·의존성이 저하 | 정책에 따라 제한 |
| `DRAINING` | 신규 배정을 중단하고 진행 요청 종료 중 | 금지 |
| `MAINTENANCE` | 점검·변경 작업 중 | 금지 |
| `DOWN` | 처리 불가 | 금지 |
| `UNKNOWN` | 상태 확인 불가 | 안전 기본값으로 금지 |

## 5. 배포·정책 상태

```text
DRAFT
→ VALIDATED
→ APPROVAL_REQUESTED
→ APPROVED
→ PUBLISHED
→ RETIRED
```

게시된 버전은 직접 수정하지 않고 새 버전을 만든다. 되돌리기는 검증된 과거 버전을 다시 게시하는 별도 명령으로 처리한다.

### 인스턴스 적용 상태

| 상태 | 의미 |
|---|---|
| `PENDING` | 적용 대기 |
| `APPLYING` | 적용 중 |
| `APPLIED` | 기대 버전과 체크섬 적용 완료 |
| `FAILED` | 적용 실패 |
| `STALE` | 오래된 버전·확인 응답 |
| `PARTIAL` | 일부 인스턴스만 적용 |
| `ROLLED_BACK` | 검증된 과거 버전으로 복귀 |

## 6. 메시지 상태

| 상태 | 의미 |
|---|---|
| `PENDING` | 게시 대기 |
| `CLAIMED` | 게시자가 점유 |
| `PUBLISHED` | 중개 시스템 전송 확인 |
| `RETRY_WAIT` | 재시도 대기 |
| `DEAD_LETTERED` | 자동 처리를 중단하고 격리 |
| `REPLAY_REQUESTED` | 재생 승인 요청 |
| `REPLAYED` | 승인 범위 재전달 완료 |

## 7. 배치 용어

| 용어 | 의미 |
|---|---|
| 작업정의 | 실행할 논리 작업, 매개변수, 권한, 제한과 재시도 정책의 버전 정본 |
| 일정 | 작업정의를 언제 발생시킬지 정의 |
| 실행 인스턴스 | 특정 작업정의와 업무 매개변수 조합 |
| 실행 | 실제 한 번의 처리 시도 |
| 단계 | 실행 안의 세부 처리 단위 |
| 체크포인트 | 재시작 위치와 처리 진행 상태 |
| 오실행 | 예정 시각을 놓쳤을 때의 처리 정책(누락 실행) |
| 대량 실행 | 분할·점유·재처리를 사용하는 대규모 대상 처리(대량 실행) |
| 원격 에이전트 | 승인된 산출물을 원격 호스트에서 실행하고 상태를 보고하는 프로세스 |

## 8. 데이터베이스 용어

| 용어 | 의미 |
|---|---|
| 정본 SQL | 논리 스키마와 변경 계획의 기준 소스 |
| 공급자 산출물 | Oracle·PostgreSQL·MariaDB 문법으로 생성된 설치·이관 SQL |
| 신규 설치 | 빈 스키마에 전체 구조와 초기 자료를 생성 |
| 이관 | 제품 생명주기 안에서 버전을 전진 |
| 되돌리기 | 허용된 범위에서 이전 상태로 복귀 |
| 재적용 | 되돌리기 뒤 같은 전진 변경을 다시 적용 |
| 정본 불일치 | 실제 스키마가 예상 열·형식·제약·인덱스·버전과 다름 |
| 논리 DB | 업무 소유권을 나타내는 스키마·계정·자료원 단위 |

## 9. 보안 용어

| 용어 | 의미 |
|---|---|
| 비밀값 참조 | 원문 대신 저장 위치와 식별자를 나타내는 값 |
| 마스킹 | 민감정보를 역할과 목적에 따라 가려서 표시 |
| 원문 보기 | 별도 권한·사유·감사를 요구하는 민감정보 확인 |
| 비상 권한 | 사고 대응을 위해 범위와 만료를 제한한 임시 권한 |
| 작성자·승인자 분리 | 위험 변경을 작성한 사람이 같은 변경을 승인하지 못하게 하는 통제 |
| 법적 보류 | 일반 보존기간 만료 후에도 법적 요구로 삭제를 중단하는 상태 |

## 10. 검증 상태

CPF 작업·검토 문서에서 사용하는 상태는 다음으로 제한한다.

- 완료
- 부분 구현
- 미구현
- 미검증
- 실패
- 재확인 필요

파일이나 클래스 존재, 정적 검색, 일부 테스트 통과, Swagger 노출, 과거 검증 증적만으로 완료 처리하지 않는다.

## 11. 한글 우선 작성 예

### 권장

- “시간 제한을 초과하면 `TIMEOUT`으로 분류한다.”
- “게이트웨이는 적용 결과 확인 응답(ACK)을 저장한다.”
- “업무영역은 공개 API와 확장 SPI의 경계를 유지한다.”
- “기대 버전과 실제 적용 버전의 정본 불일치를 상태 대사한다.”

### 지양

- “시간 제한 발생 시 재시도 후 상태 대사한다.”
- “게이트웨이 인스턴스가 바인딩을 적용하고 확인 응답(ACK)을 남긴다.”
- “공개 계약 사용자가 내부 구현 어댑터를 직접 사용한다.”

식별자와 고유 기술 용어를 억지로 번역하지 않되, 문장의 중심은 한글로 작성한다.
